### T.573 [整理][WebGPU] 1 つの層の状態だけで束縛の上限を越える linear の層を、読み込みの前に断る — 状態: 完了（2026-10-25、Opus medium。前の状態: 未着手、2026-10-24、T.271.5 のレビューの勧め。規模 小）
- いまは束が 1 層でも上限を越えると、束縛の検証で落ちる（4 × 値の head × 鍵の次元 × 値の次元 が `maxStorageBufferBindingSize` を越えるとき: 128 MiB なら 3200 万 float。実在のモデルには無い）。`gpuOnlyUnfit()` と `gpuFit()` で `alonePast` と同じ断りにするか、`gpu/linear.ts` で訳のある throw に。
- **結果**: 両方の案を入れた。GPU だけのモデルは `gpuOnlyUnfit()` が、1 つの場所の状態（4 × 値の head × 鍵の次元 × 値の次元 バイト）が端末の束縛の上限（`maxStorageBufferBindingSize` と `maxBufferSize` の小さいほう）を越えるとき、読み込みの前に新しい訳 `REASONS.aloneState`「a layer's state is past a buffer of this GPU」で断る（**取りまとめ役の決め**: `alonePast` と対の文を足した。訪問者に見える文なので、まとめの一覧に入れる）。両方に置くモデルは GPU の Worker の `gpu/linear.ts` が、シェーダもバッファも作る前に大きさを言う Error を投げ、今までどおり CPU に残る（ステータス行は「prompts on the CPU (…)」）。比べは `m.limit`（試験の `force.stateBytes` は束の大きさにだけ効き、1 つの場所は必ず 1 つの束を占めるので、場所の大きさは実際の装置と比べる）。試験: `sizes-check`（1 MiB の状態を 512 KiB の端末は断り、1 MiB の端末は通す）、`reasons-check` の `SAID`、`gpu-worker-parts-check`（偽の装置で `linear.block()` が文で断り、何も作らない）。壊し方 2 つ（どちらかの検査を外す）はそれぞれの試験が落とす。軽い組 450 秒、網（`gpusteps`・`shaders`・`choices`）は同じ。CI を省いた。訳: シェーダの文も端末の鍵も変わらず、ふつうの道は投げる所の前で変わらない。実在のモデルはこの枝を踏まない。
- レビュー（Sonnet high、2026-10-25）: must-fix なし。`m.limit` は装置に頼んだ上限と同じ式で正しい。両方に置くモデルの失敗は `unusable()` から `stopGpu()` で CPU に残り、警告 1 行。should は両方に置くモデルの早い断り（GPU の Worker が投げるのは層の重みを上げた後）: 実在のモデルが踏まないので入れず、AGENTS.md にそう書いた（早く断るなら端末の上限を forward の `device` に渡して `gpuFit()` で）。AGENTS.md の数を「約 3355 万 float」に直した。気づき（未計測、採番しない）: linear の層の行のバッファ（場所 × タップ × mixed × 4、27B で約 7.5 MiB）も丸ごと束縛するが上限と比べていない。ブロックの読み戻し `readback` は全部の束と K・V を 1 つのバッファに作るので、合計が `maxBufferSize` を越えると両方に置くモデルは「the GPU did not take the layers」で CPU に残る（GPU だけのモデルは状態を読み戻さないので当たらない）。
