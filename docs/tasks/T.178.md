### T.178 [バグ][CPU] CPU のサンプリングの足切りが、低い top-p で語彙の外を読む — 状態: **完了（本線に入れた 4a1c265。小さな直しなので本会話が確かめ、Opus xhigh のレビューは付けない: 持ち主と決めた「重さで分ける」）**
- 根拠: `kernels/kernel.ts` の `sample()` と `public/llama2_numpy.py` の `Llama.sample` は llama2.c 流の足切り（確率が (1 − top-p)/(n − 1) × 全体 未満の語を外す）をする。条件 (1 − top-p) × Σp > 床の上の数 − 1 のとき全部を外して `index[−1]` を読む。ページの top-p は 0.05〜1 なので 0.45 以下でありうる（既定の 0.9 では起きない）。**実際の生成（Node の Pyodide、160 トークン × 12 回）で、llm-jp-3 150M は T 0.1 / top-p 0.1 で 12 回中 8 回、T 0.2 / 0.2 で 4 回が IndexError（decode で語彙の外）**、tiny-lm は 0 回。kernel は語彙の外の値（`order` の直前の malloc の見出しの語）を返し、NumPy は IndexError で止まる。llama2.c は n が語彙の数なので事実上起きないが、うちは床で数が少なくなって起きる。GPU の SAMPLE（T.151）は足切りをしないので壊れない。
- 作るもの: 足切りで 1 つも残らないときは、いちばん確からしい 1 語を残す（または足切りを外す。llama2.c の意図は速さだけなので、結果の分布が変わらない形を選ぶ）。kernel と NumPy と、T.151 の `sampleLikeCpu`（T.151 が本線に入った後なら同じ回に）をそろえる。
- 完了条件: 上の設定で 0 回になる試験（smoke か pytest）、kernel と NumPy が同じトークン（smoke の 216 通り）、画面での出方（ブラウザ）を 1 回確かめる。
- **作ったもの（2026-09-27、Opus medium）**: 足切りの線を `min((1 − top-p)/(n − 1) × 全体, いちばん大きい確率)` にした（いちばん確からしい語は必ず残る）。kernel の `sample()`・NumPy の `Llama.sample`・`walkLikeCpu`（`sampleLikeCpu` はこれを使う）の 3 つを同じ形に。**分布は変わらない**: llama2.c の足切りの理由は「外す語が n − 1 個以下なら、その和は (1 − top-p) 未満で、残りの和は top-p を超える。だから nucleus は残りの中にある」。全部が線の下になるのは n × top-p < 1 のときだけで（線の下の n 個の和 < n(1 − top-p)/(n − 1) が 1 を超えうる）、そのとき最大の 1 語を残すと外すのは n − 1 個なので同じ理由が効き、その 1 語の確率は top-p を超える: 本当の nucleus もその 1 語だけ。足切りを外す案も分布は同じだが、それだと床の上の全部を並べ替えることになり、足切りのある理由（速さ）を捨てるので採らなかった。**llama2.c の本家（master の `run.c` の `sample_topp`）は今も同じ形**（`n0` が 0 なら `probindex[-1]` を読む）で、本家の n は語彙の数（32000）なので n × top-p < 1 は起きない。うちは床（最良の 1e-7 未満を先に外す）の後の数を n にしたので、数が 2〜9 まで減って起きた。GPU の SAMPLE は足切りをしないので触っていない（分布は同じまま）。
- **確かめ（a1-free）**: pytest に `test_a_low_top_p_over_few_likely_tokens`（床の上に 1・2・3・5 語、top-p 0.05〜0.45、温度 0.1〜1、100 の乱数で引ける集合が本当の nucleus と同じ）。smoke に 3 つ: kernel と NumPy（床の上に 2・3・5 語、top-p 0.05・0.1・0.2、54 通りで最大の 1 語）、`sampleLikeCpu` と kernel（同じ 54 通り）、実物の llm-jp-3 150M（ページのプロンプトと罰 1.1、T 0.1 / top-p 0.1 と T 0.1 / top-p 0.05、seed 4 つ、160 トークン）。**直す前の形で**: pytest は 16 件中 9 件が落ち、smoke は NumPy の IndexError で落ち、kernel と `sampleLikeCpu` は 54 通り中 27 通りが最大の語でない（語彙の外を含む）、llm-jp は 8 回とも IndexError（64 トークンでは 0 回: 罰でループの数語が平らになってから起きる）。直した後は全部 0 回、216 通りも 216 が同じトークン。pytest 520 件、smoke、build。ブラウザ（Playwright の Chromium、`E2E_QUERY="temperature=0.1&topp=0.1" node tests/e2e.mjs llm-jp-3-150m chromium`）で 256 トークンを書いた（71.0 tok/s）。WebGPU の検査（`/benchmark/` の `sampling`、`walkLikeCpu` を使う）は CI で。
