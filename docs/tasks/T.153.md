- **取った元ネタと理由**（`.tmp/t153/ref/` に llama.cpp の `binary.wgsl`・`rms_norm_mul.wgsl`・`row_norm.wgsl`、commit 2145525a、MIT。写した行の上に著作権の行と許諾文の全文）:
  1. **bias は llama.cpp の `binary.wgsl` の `OP_ADD`・`INPLACE`**（`shaders.js` の `ADD`）: 行列積の出力に、どのトークンにも同じ bias（`b_ne1` 1 の繰り返し）を足す。llama.cpp の WebGPU は MUL_MAT の後の ADD を畳まない（`ggml-webgpu.cpp` の融合は `rms_norm_mul` と gdn だけ）ので、元ネタどおり別のディスパッチ。q・k・v で 3 回（層あたり）。**変えた所**: トークンをディスパッチの y、要素を x に（SWIGLU と同じ。llama.cpp は全要素を x と y に番号付けして stride で位置を出す）。
  2. **head ごとの norm は llama.cpp の `rms_norm_mul.wgsl` の `INPLACE`**（`HEAD_NORM`。Qwen3 の llama.cpp の graph は q を head に reshape して RMS_NORM と q_norm の MUL を 1 つにする）: 1 つのワークグループが 1 行（1 つの head）、重みの行はどの行にも同じ（`mul_src_ne1` 1）、書き戻しは同じバッファ。**今の RMSNORM と同じテンプレート `rmsNorm(inPlace)` にした**: トークンの行の数をディスパッチの x（層の norm は 1、head の norm は heads か kvHeads）、トークンを y に。層の norm の uniform の並びは変えていない（`/benchmark/` の GPU の節の層の表は 1 トークン・x 1 で今のまま動く）。q と k で 2 回。**書き出しには畳めない**（T.150 の注: head の norm は head 全体の和が要る）ので、RoPE の前の別のディスパッチ。順は CPU の `forward.js` と同じ（bias → head の norm → RoPE）。
  3. **head の大きさが dim / heads と違うとき**: 行列積はもともと行列の形（wq は qDim 行、wo は qDim 列）で動き、flash attention は head の大きさを `flashShape()` で受け取っていた。直したのは wo の前の量子化（DP4A の形）で、attention の出力は qDim の幅なので `quantizeAttention`（qDim）を別に持つ（dim の幅のままだと DP4A で K と V が 2.55 になった: 下）。
  4. **eps**: T.147 から層の norm の uniform にモデルの `rms_norm_eps` を渡していた（GPU に回さない理由にも入っていなかった）。head の norm も同じ値を uniform で。
- **forward.js**: GPU に回さない理由から「q・k・v の bias」「q・k の norm」「head の大きさ」を外した。GPU に渡すのは層ごとのベクトルの一覧 `vectors`（norm の重み 2 つと、あるときだけ bq・bk・bv・q_norm・k_norm、それぞれ番地と層あたりの数）で、GPU に置く大きさ（`gpuRoom` の判定）にも足した。
