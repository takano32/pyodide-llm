- `Model.plan` は `Started` 型だが、GPU だけのモデルが開いてから `handed()` までは `Opening`（`Opened & { tokens: true }`）。その間に走る関数（`weights.ts` の `uploadLayers(m, true)`・`tablesOn`・`piecesOf`・`tablePieces`・`routed` と、それらが呼ぶ `buffer`・`copyIn`・`scalesIn`・`gridsOf`・`routedHalves`・`partialByte`）が `Started` だけの鍵を読んでも tsc は通る。
- **試した形（2026-10-30）**: `device.ts` に `Open = Omit<Model, "plan"> & { plan: Started | Opening }` を置いて 5 つの関数の引数をそれにすると、型の誤り 20。多くは呼ばれる小さな関数が `Model` を取るため（`Model` は `Open` に当てはまるので、それらを `Open` に広げれば消える）。残る本物の形の問題が 2 つ: (a) **`uploadLayers` は開くとき（`alone` が真）と `start()` のときの両方で走り**、`start()` の側だけが `tokensLayout(m)`・`tablesOf(plan)`（`Started` の鍵）を読む: 関数を 2 つに分けるか、`alone` の枝を型で分ける。(b) `Opened` の `kinds`・`places` は層の種類が混ざるモデルにだけある（`forward/alone.ts` の `gpuOnlyPlan()`）が、`uploadLayers` は `plan.kinds[l]`・`plan.places[l]` を読む: 読むのは `matrix.of` があるときだけで、`of` は混ざるモデルにしか付かないので今は正しい。型では `!` と訳になる。
- 勧め: 開くときの層の上げを自分の関数にして `Open` を取り、`start()` の側は `Model` のまま。
