- **作ったもの（Opus medium）**: `shaders.js` の `SAMPLER_STAGES`（`SAMPLE_MAX`・`SAMPLE_SUM`・`SAMPLE_GATHER`・`SAMPLE_PICK`）。1 ワークグループ 1024 語の塊（`SAMPLE_CHUNK`、1 スレッド続きの 4 語: subgroup の読みが並んだ 256 バイトになる）、語彙 128256 で 126 ワークグループ。(1) MAX（塊ごと）: 罰（その塊にある窓の語だけ、T151 と同じ規則）と塊の最大とその最初の index。(2) SUM（塊ごと）: どのワークグループも全部の塊の最大を畳み直して語彙の最大を得て、T151 と同じ exp((v − 最大) / T) と床で、塊の和と床の上の数（nucleus なしは確率を `probs[i]` に）。ワークグループ 0 が最大と床を置く。(3) GATHER（塊ごと、nucleus のときだけ）: 前の塊の床の上の数を足した位置から、塊の中を scan で index の順に `order` と `probs` に。(4) PICK（1 ワークグループ）: 塊の数と和から数と質量、あとは T151 の nucleus の探しと引き（`SAMPLER_DRAW`、`SAMPLE` と同じ関数を共有）。nucleus なしの引きは、塊の和を scan して越える塊、その塊の 1024 語を scan して越える語（丸めでその塊の中に越える語が無ければ塊の最後の語）。温度 0 は塊の最大の畳み直しの最初の index。止まった回は 4 つとも何もしない。
- **取った元ネタと理由**: 語彙を塊に分けて 2 段にする形は **MLC LLM の 2 段の softmax**（`python/mlc_llm/compiler_pass/attach_softmax_with_temperature.py`、commit 9fa644f5、Apache-2.0: `chunk_lse` が 4096 の塊ごとの最大と和、`softmax_with_chunked_sum` のどのブロックも全部の塊の結果を畳み直す）。うちの変えた所: 塊の和を log-sum-exp で合わせる代わりに、語彙の最大を先に畳んでから和を取る（T151 と同じ exp(v − 最大) と床のため。段が 1 つ増える）。塊の中の最大・和・順は T151 と同じ llama.cpp の `argmax.wgsl`・`soft_max.wgsl`・`cumsum.wgsl`（MIT）。FlashInfer と MLC の top-p（`top_p_pivot`）はどちらも 1 つの行を 1 つのブロックで探すので、探しは T151 のまま 1 ワークグループ（床の上だけを読むので、模型の logits では 3695 語）。塊の大きさを 4096（MLC）でなく 1024 にしたのは、1B の語彙で 11 コアに 126 ワークグループ（4096 なら 32）と、1 スレッド 4 語で index の順の集めが 1 回の scan で済むため（4096 なら塊の中で 4 回か、1 スレッド 16 語の続き）。**subgroup の演算は使わない**（どの端末でも同じ形。幅に依らない）。写した行は無く、出どころと許諾文は T151 の告知（MLC・TVM・llama.cpp）に並べた。

  - (c) nucleus なしの 2 段: 厳密な算術では、CPU の止まる語 k（C_k > goal ≥ C_{k−1}）の塊 c* は E_{c*} ≤ goal < E_{c*+1}（E は塊の頭までの和）で、「running > goal の最初の塊」がそれ、その中で「E_{c*} + 塊の中の累積 > goal の最初の語」が k。違いは丸めだけで、上限は足す回数 × 2^-24 × 質量: 塊の和は 1 スレッド 4 語 + 木 8 段、塊の scan は 8 段、中の scan 8 段 + 4 語で約 30 × 6e-8 ≈ 2e-6（`SAMPLE` は 1 スレッド 501 語で 3.3e-5）。**JS の模擬**（`.tmp/t191f/twostep.mjs`: シェーダと同じ Blelloch の木と区間を f32 で、800 回ずつ（乱数は一様・1 の直前・0 と 1 の近く）、CPU の float64 の歩きと比べて）: 平らな logits（128256、T 0.7）で 2 段は 800 回中 2 回違い（境からの遠さの最大 7.5e-8 × 質量、隣の語）、1 ワークグループの `SAMPLE` は 27 回（1.2e-6 × 質量）。**2 段のほうが CPU に近い**（続きの 4 語は 501 語より丸めが小さい）。山のある logits では 174 回違うが遠さは 1.5e-7 × 質量までで、index では最大 1932 語離れる（山の後ろの exp(−28) ≈ 1e-12 の平らな所に乱数が落ちると、どの語も同じ累積: 検査の線 ±1e-4 は区間で見るので通る）。**塊は越えたのに中で越える語が無い形（`end − 1`）は乱数が 1 の直前でよく起きる**（平ら 27 / 800、sparse 204 / 800: 最後の塊の running = 前の和 + 塊の和 と、中の最後の inside = 前の和 + 排他 scan + 4 語 の丸めが違う）が、そのとき厳密な越える語は塊の最後の語（C_k ≤ E_{c+1} ≤ goal + δ なので k から塊の終わりまでの確率の和が δ 以下）で、`end − 1` は境から δ（約 1e-7 × 質量）の内: 模擬でも sparse は 800 回とも CPU と同じ語。確率 0 の語を返しうるのはこの δ の窓だけ（`SAMPLE` の `vocab − 1` と同じ種類、1 回の引きで約 1e-7）。 nucleus なしの床は `SAMPLE` と同じ −3.4e38 で、−inf の logit は `probs` に 0 を書いて越えない（T195 の後の `walkLikeCpu` は kernel と同じく −f32.MAX で −inf を外す: 乱数 0 でも同じ語。有限でない最大は `finiteLikeCpu()` が投げるので、この確かめの logits は全部有限）。
