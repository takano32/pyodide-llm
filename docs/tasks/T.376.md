- **考え**: 分割そのもの（どの文をどのファイルに置くか）はやり直さない。責務の切れ目で切ってあり、「動かすだけ」を先にやるのは動きを変えてよい今でも正しい順。やり直す値打ちがあるのは、動きを変えない決まりのために曲げた所（継ぎ目）で、それは抽象化の仕事そのもの。だから別の回に 2 度やらず、抽象化の設計を広げて 1 回でやる。
- **いま分かっている継ぎ目（どの番号にも入っていなかった）**: (a) 部品が一緒に読み書きする変数を機械的に 1 つのオブジェクトに入れた所: `worker/state.js` の `state`（36 個）・`src/page/state.ts` の `page`・`public/gpu/device.js` の `common`・`public/benchmark/gpu/device.js` の `shared`・`src/benchmark/state.ts` の `page`、`forward/` の `pool`・`gpuPart`・`held`（getter と setter のオブジェクト）。持ち主をはっきりさせる形（その状態を持つ部品が方法で出す）に。(b) `Llama` の土台クラス 3 つ（メソッドを 1 字も変えずに移すための継承: `TensorOrder`・`Sampling`・`Generation`）。(c) 鍵を動かさないために残した写し（`ternaryMatVec` は `fusedDp4aMatVec` の写し）と、シェーダを作る関数の重なり。(d) import を書き換えないためだけの窓口（`shaders.js`・`gpu.js`・`forward.js`・`worker.js`・`src/models.js`・`src/bench.js`・Python の 2 つ）: T.367 で束ねるなら、読む側が部品を直に読む形にできるものがある。(e) 分割の途中で見つけて直していない誤り（`gpu.js` の `ended` が 2 回、古いコメント、T.371・T.372 など: 採番して後で）。

- **持ち主が抽象化に期待するもの（2026-10-09、「カプセル化や責務の分割、メンテナンス性が向上することを期待してるよ」）。設計の案はこの 3 つで測る**: (1) カプセル化: 状態は 1 つの持ち主だけが書き、ほかは方法越しに使う（共有の入れ物のフィールドを誰でも書ける形をなくす）。案ごとに「外から書けるフィールドの数」の前後を出す。(2) 責務の分割: 1 つのモジュールが変わる理由は 1 つ。案ごとに、そのモジュールの責務を 1 文で言えるかと、部品どうしの import の向き（輪や行き来が無いか）を出す。(3) メンテナンス性: よくある変更（アーキテクチャを 1 つ足す、dtype を 1 つ足す、GGUF の型を 1 つ足す、シェーダの形を 1 つ足す、Worker の知らせを 1 つ足す）で触るファイルと場所の数の前後を出す。数が減らない案は採らない。
- **ほかに設計で考えること（2026-10-09、持ち主「ほかにも考慮すべきことがあれば考慮してくれよな」）**:
  - **これから足すものを設計の試金石に**: Saluki（K 量子化と i 量子化の型 10 種類、詰めたままの dtype）・Gemma 3 と 4・Spark X・MLX を、案の上で足してみて触る場所を数える。今あるものだけで形を決めない。
  - **速さ**: 1 トークン・1 ブロックごとに通る道（forward の層、カーネルの呼び出し、GPU の submit）に間接を足す案は、CI で前後を同じプロセスで交互に測ってから。遅くなる案は、きれいさと並べて持ち主に見せる。
  - **正しさの試験を先に**: 動きを変えてよくなったので、網は門でなくなる。形を替える所に正しさの試験（NumPy・transformers との比べ、わざと壊して落ちること）が無ければ、先に足す別のコミットを。
  - **試験しやすさ**: ブラウザも GPU も無しで部品 1 つを試せる形（時計・Worker の工場・fetch を外から渡す今の流儀を広げる）。偽物で済む所が増えるかを案ごとに言う。
  - **型と境目**: 部品の間の約束（Python が渡す計画と options、Worker の知らせ、制御領域の語、GPU への頼み）を設計で名前のある形にする。T.368 の型と T.370 の境目はそこに乗る。
  - **依存の向き**: 層を決めて 1 方向に（データと設定 → 計算 → 段取り → 画面）。下の層が上を知らない。
  - **失敗の道を 1 つの流儀に**: CPU へのフォールバック・読み直し・断りの文が部品ごとに別の書き方になっている所をそろえる。
  - **名前**: 同じものに同じ言葉（`common`・`shared`・`state`・`page` のような入れ物の名前をなくし、持ち物の名前で呼ぶ）。
  - **戻しやすさ**: 1 つの継ぎ目を 1 つのコミットの組で、そのたびにデプロイできる大きさに。端末でしか分からない危なさのあるものは印を付けて「持ち主の端末でまとめて見るもの」に積む。
  - **やりすぎない**: 実装が 1 つの所に層を足さない決まりはそのまま。案ごとに、足すファイルと間接の数も出す。
