  - **vec4 の形 = TensorFlow.js の WebGPU の `makeMatMulPackedVec4Source`**（`tfjs-backend-webgpu/src/matmul_packed_webgpu.ts`、https://github.com/tensorflow/tfjs、Apache-2.0、Copyright 2019 Google LLC）。レビューの見積もりで足した: llama.cpp の 32×32 は Mali で 3.2〜3.7 倍どまり（共有メモリの読みで律速の見込み）、iPhone では llama.cpp の src0 の 8 行が同じバンクに当たる（512 B おき）、ORT は Metal で DP4A を使わない。TF.js の形は共有メモリを vec4 で読み、1 スレッドの 4 トークンが 1 つの vec4 の和（fma）。形は大きい積の既定（workPerThread [4, 4]、workgroupSize [8, 8, 1]、tileInner 32）。A を重み（行、4 つの int8 の u32 をスケールで広げる）、B を活性値の転置（4 トークンの vec4）にした。`shaders.js` の `tfjsTile`。
  - **packed の形 = ONNX Runtime Web の DP4A MatMulNBits**（`onnxruntime/contrib_ops/webgpu/quantization/dp4a_matmul.wgsl.template` と `dp4a_matmul_common.wgsl.template` の `SDP8AI`、8 ビット・zero point なし、https://github.com/microsoft/onnxruntime の commit 3756d4dc、MIT、Copyright (c) Microsoft Corporation）。64 トークン × 64 行、256 スレッド、k は 32 ずつ、1 スレッド 1 トークン × 16 行を `dot4I8Packed` の整数の和 × 2 つのスケールで（CPU の `matmul_q8` と同じ計算）。subgroups のある端末では ORT の `sg_size == 16` の `subgroupShuffle` の道も別の行に。`shaders.js` の `dp4a(subgroups)`。
  - **活性値の量子化は自前の `QUANTIZE`**（1 スレッド 1 グループ、CPU の `quantize_x` と同じ半偶数の丸め）。ORT の `dp4a_quantize` は `pack4x8snorm`（⌊0.5 + 127 × 値⌋ と決まっている）で、CPU の偶数への丸めと違い、グループは 128。
