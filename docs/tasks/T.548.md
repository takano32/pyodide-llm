### T.548 [性能][WebGPU] メモリを言わないブラウザ（Safari・Firefox）の答えのステップを GPU に置くか — 状態: 完了（2026-10-25、本線に入れた。前の状態: 進行中（Opus medium、ブランチ `t.548-steps-unsaid`）。前の状態: 未着手、2026-10-16、**持ち主が選択肢で「どちらも GPU に」**: Safari も Firefox も答えのステップを GPU に置く。iPhone でタブが落ちうるので、本線に入れた後に持ち主の iPhone で確かめる（端末の一覧に積む）。落ちたら Safari だけ戻す）。前の見出し: 持ち主の判断待ち（2026-10-16、WebGPU の洗い出しから。規模 小。区切りのまとめで聞く）
- いまは `tokensUnfit()` の `REASONS.memoryUnsaid`（T.205）で、`navigator.deviceMemory` を言わないブラウザは答えのステップを GPU に置かない（プロンプトのブロックだけ GPU）。訳: iPhone の `/benchmark/` のモデルの節で、分類器と埋め込みも GPU に置いたらタブが落ちた。メモリの見積もりはもともと 4 GB の仮定（`weightsPlace()` の既定）なので、この行は余分の守り。
- **選択肢（勧めを先頭に）**: (1) Firefox だけ置き、Safari は今のまま（Firefox の WebGPU はパソコンの版で使われている。Android の Firefox で WebGPU が使えるかは未確認。落ちた報告は iPhone の Safari のものだけ）。(2) 今のまま。(3) どちらも置く（iPhone の Safari のタブが落ちうる: 持ち主の iPhone で確かめてから）。
- 見分けは端末の事実で（Safari かを UA の文字で見るのでなく、例えば WebKit だけの性質で）: 書くときに決める。鍵は動かない。確かめは CI の Firefox（`browsers.yml` の WebGPU のある組）と持ち主の端末。
- **材料（2026-10-16、T.552 の naidan の調べから）**: naidan は Firefox（iOS の Firefox を除く）で WebGPU を使う訪問者に「Chromium のほうが速い」と出す。訳は Bugzilla 1870699: Firefox は GPU の仕事の終わりを時計で見回るので、終わりの知らせ（`mapAsync`・`onSubmittedWorkDone`）が遅れる（`src/features/llama-cpp-browser/firefox-webgpu-warning.ts` のコメント。バグの中身は読んでいない）。こちらは 1 回の submit の後に読み戻しを待つ形なので、Firefox では submit ごとの待ちが固定費として乗る見込み。端末で測って選ぶ形なので遅ければ CPU に戻るはずだが、入れる前に CI の Firefox で答えのステップの 1 回の submit の待ちを測って記録する（T.551 の数字と並べる）。
- **結果（2026-10-25）**: `gpuFit()` の `tokensUnfit()` から `REASONS.memoryUnsaid` の行を外し、`memoryUnsaid` を worker・`external()`・`createForward()` から全部消した（訳の文も `REASONS` から）。GPU だけに置かない決め（`gpuOnlyPossible()`: メモリを言わない端末と 6 ビット）はそのまま。答えのステップはステップの計測（`faster`）で CPU と比べて選ぶので、Firefox の submit の待ちが大きければ CPU に戻る。Firefox の submit の待ちは未計測: CI の Firefox（Playwright）は WebGPU のアダプタを持たない見込みで（未確認）、測るのは持ち主の端末か本物の Firefox。試験: `gpu-default-check`（メモリを言わない端末だった場合もステップを GPU に頼み、GPU が取る）、`gpu-part-check`・`reasons-check` の表から行を消した。シェーダの文と端末の鍵は変わらない。CI を省いた。訳: 偽の GPU の Worker で回る判定だけで、シェーダは触っていない（本物の確かめは持ち主の iPhone: 端末の一覧に足した）。軽い組は通った。**取り消し**: `git revert` 1 つで Safari と Firefox の両方が戻る。Safari だけを戻すには、WebKit を見分ける条件を新しく書く（配線を消したので）。
