### T.507 [不具合][描画] Service Worker の入ったブラウザで `?coi=off` を初めて開くと worker が始まらない — 状態: 完了（2026-10-25、本線に入れた。T.522 も同じ直しで閉じる。前の状態: 進行中（Opus medium、ブランチ `t.507-coi-off`）。前の状態: 未着手、2026-10-13、T.505.3 の実装とレビューが見つけた。前からある: 本番で再現）
- **結果**: 見立てのとおり。`?coi=off` の訪問はまだ Service Worker が受け持つページ（隔離のヘッダつき）のまま登録を外していて、その上で作る worker が始まらなかった（手元の Chromium で「Initializing...」のまま）。直しはページの側だけ（`src/page/isolation.ts`）: 登録を外した後、ページが隔離されていれば（Service Worker を通ってヘッダつきで来た）読み込み直してヘッダの無いページにする。そのページ自身が読み込み直しなら（それでもヘッダを付けるブラウザ）もうしない: 印は `sessionStorage` でなく `performance` の navigation の `type`（隔離したページとヘッダの無いページは `sessionStorage` を分け合わない: レビューの勧めで印を消す形を試して、2 回目の `?coi=off` で消したはずの印が隔離したページの側に残っていた）。`public/coi.js` には触っていない（落とし穴の「持ち主の端末が先」の範囲の外: ほかのサイトの応答と隔離のヘッダの扱いは変わらない）。試験: 実ブラウザの道具 `tests/coi-off-in-browser.mjs`（隔離した訪問の後に同じ profile で `?coi=off`: 準備完了・隔離なし・登録なし。そのあと Service Worker の下の訪問と、もう 1 回の `?coi=off`）。直す前の版では 120 秒「Initializing...」で落ちる。ふつうの訪問は `tests/e2e.mjs stories260K` で前と同じ文。レビューの直しの後も道具と e2e が通り、軽い組 465 秒。CI を省いた。訳: 手元の Chromium の実ブラウザで踏める（Firefox・WebKit の違いは未確認: `browsers.yml` の週次が `?coi=off` を開かない）。取りまとめ役の決め: 読み込み直しは、読み込み直したページではしない（ヘッダを付け続けるブラウザで回り続けないため。その道は試せていない）。
- レビュー（Sonnet low、2026-10-25）: must-fix なし。直しの向き、`coi-fallback` の道と 2 回読み込み直さないこと、`coi.js` に触らないので持ち主の端末が先に当たらないことを確かめた。勧め（印を消す所が無く、同じタブの 2 回目の `?coi=off` が止まる）を入れた: 上のとおり印をやめて navigation の `type` に。道具に 2 回目の `?coi=off` を足した。入れない: `/benchmark/` の `?coi=off` にも同じ症状が出うる（別の採番に: T.582）。
- **手順**: 新しい profile の Chrome 155 で本番を開き、Service Worker が入るまで待ち（15 秒）、`?coi=off` に移る → ページに「Failed to start the worker: undefined」。開き直すと動く。一覧のモデルでも `?hf=` でも同じ。再現の道具はレビューが作業の木の `.tmp/coioff.mjs` に置いた（コミットしていない: Playwright の `launchPersistentContext`）。
- **見立て（未確認）**: `?coi=off` は Service Worker の登録を外して読み込み直す。その読み込みは、まだ隔離のヘッダつきで配られたページ（COEP: require-corp）で、worker のスクリプトの応答に Service Worker が居ないので CORP のヘッダが付かず、ブラウザが worker を断る（AGENTS.md の開発サーバの項と同じ形: 文なしの `error`）。
- **害**: `?coi=off` は試験と切り分けのための指定で、訪問者はまず踏まない。ただし Service Worker が外れる・壊れる道で同じことが起きないかを見る。
- **決まり**: `public/coi.js` のうち、ほかのサイトの応答・隔離のヘッダ・fetch の受け口に触る直しは持ち主の端末が先（AGENTS.md の落とし穴）。ページの側で直せるかを先に見る。
