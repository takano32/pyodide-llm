### T339 [調査][Spark X] Spark-X2.5 を動かす: 全体と順 — 状態: 完了（2026-10-15、T340〜T343 が全部本線に入り、Spark-X2.5 の 1.7B と 4B が本番で動いた）。前の見出し: レビュー前（2026-10-15、Opus medium。調べの表は docs/notes/t339-spark-x-2026-10-15.md。前の状態: 未着手（2026-10-05、持ち主「[Spark X] も追加できる？」。調べは HF の config・`modeling_spark.py`・GGUF の見出し））
- **調べの答え（2026-10-15）**: 原本 2 つは apache-2.0・ゲートなし（API の `gated: false`、カードの本文も同じ）。今ある部品で済むのは窓の層（Gemma 3 の局所の層、T510.1 の輪）と層の種類ごとの RoPE（局所の層は head 全部を自分の表で、ほかは GPT-NeoX の `PARTLY`: 回す幅の角）。足したのは前分割（T340）、変換器の層ごとの並べ替え（T341）、head ごとの gate・erf の GELU・名前と GGUF（T342）。**GGUF の q と k は Hugging Face の並び**（llama.cpp の NEOX: 層 0 と 3 の `attn_qkv` を原本の bf16 と比べて、そのままで最大の値の 0.0039、Llama の並べ替えを当てると 1.2〜1.6）。`attn_gate` も Q8_0。4B は head 16 × 256 で q が 4096 幅（dim 2560 と違う）。int8 のチェックポイントは 1.7B 1,921,450,012・4B 4,626,626,588 バイト（6 ビット 1,494,564,892・3,598,653,468）、文脈 4096 の `footprint()` で全部 1.7B 2.199 GiB（32 ビットに入る）・4B 5.306 GiB（64 ビット）。
- **子タスクの分け方は台帳のとおり**（T340・T341・T342、それぞれ別のブランチ、前のものの上に重ねた）。T341 は「エンジンは今の部品で済み、変換器の層ごとの並べ替えだけ」と分かったので、その 2 つ（下）で閉じる。
- **取りまとめ役の決め（2026-10-15、区切りのまとめで見せる）**: (1) **GELU は erf の形のカーネルを足した**（tanh の近似で済ませない: Gemma 3 の比べで厳密形と tanh の差は logits 0.13・0.07 で、transformers との線 1e-3 の 100 倍。GPT-NeoX は `gelu` を tanh で走らせているが、それは変えていない）。(2) **head ごとの gate は量子化する行列**（役 `MATRIX`: int8 のファイルでは int8。XHToken の GGUF も Q8_0。Qwen3.5 の値ごとの gate `wg` と同じ扱いで、q・k・v と同じ段で掛ける）。(3) **訪問者に見える断りの文**: 変換器の家族の一覧に「Spark-X2.5」が入る（「… Gemma 4, Spark-X2.5, GPT-2 and GPT-NeoX models are supported」、GGUF の一覧も）、家族の断り 6 つ（英語、`families/spark.py`）。GPU に置かない訳は今ある文（`REASONS.pair`）。新しい文は足していない。(4) GGUF だけで開く道に前分割の名前 `spark2_5` を足した（実物の GGUF と原本の tokenizer.json を突き合わせた）。(5) transformers との比べは transformers 4.57.1（モデルの config.json の版: そのコードが書かれた版）で、モデル自身の `modeling_spark.py` を import して（`trust_remote_code` と同じものを、問いなしに）。(6) 作り物の値の広がりを 0.1 に（後ろの norm が無い深い作り物で int8 の線に寄ったため）。
- **実物**: XHToken の `Spark-X2.5-1.7B` @`14d6e83c13c7add2b62a7c39b2131f4ed1cddcf8` と `Spark-X2.5-4B` @`0bcb35678590218655dff3765b9e61c83b35e9c4`（apache-2.0、ゲートなし、2026-08-24。GGUF の 4B は 48 万・1.7B は 21 万ダウンロード）。作り手の Q8_0 の GGUF（`Spark-X2.5-1.7B-GGUF` @`1f7fa33b…` 1,820,112,704 バイト、`-4B-GGUF` @`9826e0be…` 4,375,021,152 バイト）。言語は英語と中国語（カード）。日本語は未確認（前分割はかなの塊を切るので、日本語は読める見込み）。道具の呼び出しとエージェントに寄せた後訓練。
- **形**（`model_type: spark2_5`、自前のコード `modeling_spark.py`）: 4B は 36 層・幅 2560・FFN 10240・head 16 / kv 4・head 256、1.7B は 28 層・幅 2048・FFN 6656・head 8 / kv 2。語彙 131,072、埋め込みと分類器は同じ表、RMSNorm（1 を足さない、eps 1e-6）。**Llama との違い**: (a) 4 層に 3 層が窓 512 の attention、(b) RoPE が層の種類で違う（窓の層は theta 1e4 で head 全部、全体の層は theta 5e6 で 4 分の 1）、(c) head ごとの出力の gate（`g_proj`: 幅 → head の数の小さな行列、sigmoid を head の出力に掛ける）、(d) FFN の活性化が `gelu`（transformers の正確な erf の GELU。SwiGLU の silu の代わり）、(e) q・k・v が 1 つの行列（`q_k_v_proj`）。q・k の norm は無い。文脈は config で 1,048,576（全体の層だけが全部の KV を持つので、文脈を伸ばしたときの KV は普通のモデルの 4 分の 1）。
