### T209 [性能][WebGPU] 分類器と埋め込みを GPU の上で行の塊に（生成のステップが 3B 以上でも GPU に乗るように） — 状態: **完了（本線に入れた 4d3568e。レビュー済み）**
- **形**: 表は層の行列と同じ `piecesOf()`（T155: 行まるごと、塊の最初の行は出力を束ねられる所）。分類器は塊ごとに 1 ディスパッチで、logits の自分の範囲（`{ buffer, offset: first × 4, size }`）に書く（シェーダは変えない: 融合した形の `write` は束ねた範囲の行 0 から書く）。**EMBED は塊ごとに 1 ディスパッチ**で、uniform の y を塊の最初の行、z を行の数にし、トークンが自分の行に無い塊は何も書かない（u32 の引き算なので、最初の行より前のトークンも z 以上になる。z が 0 なら前と同じ表全体: ベンチの GPU の節は変えていない）。llama.cpp の `get_rows` は 1 つの表を読み、範囲の門はうちの 2 行（元ネタの無いシェーダの行はこの門だけ。レビューで見てほしい所）。
- **CI（2026-09-27）**: gpu-prompt.yml の軽い組（36337490103、本線 fa51012 の上）: 作り物のステップの 4 つの形とも「(the tables in 5 pieces)」で ID・止まり・罰・4 ステップの一致が通った。実物の Llama 3.2 1B（36337753824、Dawn + lavapipe、`forms=TF.js`）: **それまで lavapipe の 128 MiB に分類器 262.7 MB が入らずステップが CPU だったのが、表 2 つの塊でステップが GPU に乗った**（4 つの形とも greedy の 4 ステップが NumPy と同じ・止まり・罰も合う。3 分の 1 に刻ませた回は 3 つの塊で同じ）。**わざと壊した**（捨てのブランチ、消した）: EMBED の範囲の門を外すと（36340513669）、塊ごとのディスパッチが自分の行でないトークンの行も書き、4 つの形とも読み込みの検査で「the first layer's stream is 0.96〜2.13 of its change」になってステップが CPU に戻り FAILED。
- **試験**: gpu-check のステップの形の回は、表を約 3 分の 1 の塊に刻ませる（`gpuForce.tablePieceBytes`）。作り物は語彙 320 行 × 64 で 64 行の塊 5 つ（1 つの塊は 4096 バイト）。刻まれなかったら FAILED（語彙が 192 行以上のとき）。ログの「a token by … (the tables in N pieces)」。**確かめていない**: CI の結果（下）、持ち主の Android の 3B（T156 の B と一緒に）。
- **レビュー（Opus xhigh、2026-09-27）: must-fix 0、OK。** **EMBED の門の 2 行（元ネタなし）を式で確かめた**: row = (token − y) mod 2³²、書くのは z = 0 か row < z のとき。token ∈ [y, y + z) ⇔ row < z（token < y なら row = 2³² − (y − token) ≥ 2³² − y ≥ z: y + z ≤ 語彙 < 2³¹ だから）。塊は語彙を重ならずに覆うので、語彙の中のトークンはちょうど 1 つの塊だけが書く。語彙の外のトークンはどの塊も書かない（前は 1 つの表の外を読んだ: どちらも誤った入力の話）。return は EMBED に barrier が無いので uniformity に触れない。scales の添字は塊の最初の行から数え、`copyIn` の `scalesAt + first·n/32·4` と合う（int6 の広げも `first·n·3/4` から）。分類器の出力の束ねは first × 4 バイトで、first は `minStorageBufferOffsetAlignment / 4` 行の倍数（256 なら 64 行）。塊が 1 つのときは uniform が [dim, 0, 語彙, 0] で、語彙の中のトークンでは前と同じ。**持ち主の Android（256 MiB）での塊の数**（見積もり、値のバイトで）: Llama 3.2 3B 394 MB は 87360 行と 40896 行の 2 つ、Swallow 8B 525 MB は 65536 行の 2 つ、llm-jp-4 8B（語彙 196608）は 65536 行の 3 つ（どちらも埋め込みは別の表で同じ数）。ステップごとに EMBED と分類器のディスパッチがその数ずつ。**CI（レビュー）**: ブランチ（レビューの直しの後）の gpu-prompt.yml の全部の組と、実物の Llama 3.2 1B（下の T156 のレビューの行）。
