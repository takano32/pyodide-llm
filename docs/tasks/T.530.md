### T.530 [試験][CPU] `geglu_erf` の NumPy との線を、両方の道で同じ係数をずらす壊し方で確かめる — 状態: 完了（2026-10-25、Opus medium。前の状態: 未着手、2026-10-15、T.340〜T.342 のレビューの気づき）
- いまの壊し方（ベクトルの道だけ係数をずらす）は「4 つずつと 1 つずつが同じ」の検査が落とす。両方の道で同じ誤りを入れたとき、smoke の NumPy との比べ（rtol 2e-6）と erf との比べ（5e-7）が係数の 1e-5 規模のずれを落とすかは未確認。通すなら線を締める。
- **結果**: 試験は直さない（今の線で落ちる）。`kernels/kernel/activations.ts` の `geglu_erf` の係数を、4 つずつの道と 1 つずつの道の両方で同じだけずらす壊し方 3 つ（a5 1.061405429 → 1.061415429、p 0.3275911 → 0.3275944、a1 0.254829592 → 0.254832140: どれも相対で約 1e-5）を `make kernels` と smoke で回し、3 つとも smoke の「geglu_erf is not NumPy's gelu_erf() times the other input」（rtol 2e-6）が落とした（「4 つずつと 1 つずつが同じ」の検査は両方の道が同じなので通る）。CI を省いた。訳: 手元の smoke だけで決まる。
- レビュー（Sonnet low、2026-10-25）: 試験の変更は不要で妥当。ただし NumPy の `gelu_erf()`（`engine/layers.py`）は同じ式と係数の写しで、正しさの独立した参照ではない: 係数の正しさを守るのは `math.erf` との比べ（5e-7、Abramowitz と Stegun 自身の誤差 1.5e-7）だけ。勧めに従って、同じ 3 つのずれを kernel と NumPy の両方に入れた回も回し（`make kernels python`）、3 つとも「geglu_erf is not the exact GELU times the other input」（`math.erf` との比べ）が落とした。両方が一緒にずれる 1e-6 規模の誤りは通りうる（余裕は約 3e-7）。
