- kernel の `selectTop`（`kernels/kernel/sample.ts`）は k 番目の境の同点を「どちらでも」にしている。GPU・NumPy・`likecpu.ts` は添字の順。厳密に同点の語が境にあると、kernel と GPU が別の語を引きうる（実の logits では稀。試験は許している: T.274）。直すなら kernel の選びを同点の添字で決める。優先度は低い。
- **結果**: kernel の `selectTop()`（top-k の境）と `sortNucleus()`（大きい順に歩く並び）を、(確率の大きい順、同じなら添字の小さい順) の順にした。確かめの途中で、境だけでなく歩く並びでも同じ確率の語の順が決まっていないと分かり（同じ乱数で NumPy と別の語を引く）、両方を直した。NumPy の nucleus の並べ替えも安定にした（`np.argsort(…, kind="stable")`: top-k の側は前から安定）。速さ: 添字を毎回読む最初の形は `tests/sample-bench.mjs` で x86 0.97×・0.98×（run 40154758823）、arm64 0.97×・0.99×（run 40154758817）。確率が等しいときだけ添字を読む形にして x86 1.00×・1.00×（run 40155766917）、arm64 0.99×・1.00×（run 40155767764）。どの回も 768 回の引きの全部で main と同じ語。試験: smoke（同じ確率の語 20 個と大きい 2 個で、top-k の境の語が添字の小さいほうで、どの乱数でも NumPy と同じ語。top-k なしの nucleus も）、`tests/kernels-in-browser.mjs` に `sample` を足した（前は入っていなかった。JavaScript に書いた順と同じ語か: CI の WebKit・Chromium・Firefox で ok、run 40155767232）。壊し方（同点を決めない、quicksort の走査だけ決めない）は smoke と実ブラウザの検査の両方が落とす。網の `python` の違いは、logits が全部等しい代役の生成 1 つ（`test_parts.py` の `test_a_dropped_model_is_freed_without_a_collection` の outside: 予定した違い）。軽い組 461 秒。
