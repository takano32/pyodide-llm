- **決めたこと（理由つき）**:
  - **クラスを分けず、`Llama` のオプションにした**（`arch="qwen35"` と `linear=`）。full attention の層は今の Qwen3 の計算（head の norm、GQA、一部だけの RoPE）に gate を 1 つ足すだけで、FFN・norm・埋め込み・分類器・トークナイザ・`generate()` は同じ。別のクラスにすると forward の半分を 2 か所に持つことになる。層のループに足した Python の分岐は「linear の層か」の 1 つと gate の 1 つ。
  - **層の種類ごとにテンソルを積む**。ファイルは 7 個の int の見出しのまま。full の層の束（q・gate・k・v・o・head の norm 2 つ）、linear の層の束（qkv・z・b・a・畳み込み・dt_bias・decay・norm・out）、全層の FFN の順。`llama2_numpy.qwen35_tensors()`・`checkpoint_dtype()`・`llama2_convert.layout()` の 3 か所が同じ並び（pytest が見る）。
  - **ファイルから分からないものは `FORM` に 1 つだけ足した: `linear`**（`{every, key_heads, value_heads, key_dim, value_dim, conv}` の辞書、無いモデルは None）。平らな鍵を 6 つ足すと `layout()` と `Llama()` の引数が 6 つ増える（`test_the_form_has_one_set_of_defaults` が同じ既定を求める）。options に載るのは hybrid のモデルだけなので、今あるモデルの変換は変わらない: 合成の Llama・Qwen2・Qwen3・GPT-2・GPT-NeoX の 80 通り（4 つの dtype）で、チェックポイントと tokenizer.bin のハッシュと options が main と同じ（`.tmp/t229/same_bytes.py`）。**`CONVERTER` は上げていない**。
  - **`every` は 1 つの数**（層 l は (l + 1) % every == 0 のとき full）。config の `layer_types` がその並びでなければ変換器が断る（公開されている Qwen3.5 と Qwen3.8 はどれも 4）。
  - **gate の小さな行列 2 つ（`in_proj_b`・`in_proj_a`、value head の数 × dim）は int8 のファイルでも float32 のまま**。sigmoid と exp を通って head の状態全体に掛かる数で、0.8B で 1 層 131 KB。Bonsai 2 の GGUF もこの 2 つを BF16 のまま持つ（T.228）。int8 にした場合の差は未計測。
  - **状態は KV キャッシュと別の配列で、大きさは文脈に依らない**（NumPy: `delta_state`（linear の層 × value head × key_dim × value_dim）と `conv_state`（前の conv − 1 トークンの qkv））。`KV_START` からの倍々の伸びは full の層のキャッシュだけ。**位置 0 の forward が状態を消し、それ以外は「次の位置」しか受け付けない**（`follow()`、違えば ValueError）。KV は同じ位置を書き直せるが、状態は書き直せないので、順番の違う呼び出しを黙って通さない。
  - **norm の重みは変換器が 1 を足して書く**（HF は 0 を中心に持ち `1 + weight` を掛ける。linear の層の `norm.weight` だけは足さない）。GGUF も足した後の値なので T.236 と同じ形になる。float16 のファイルでは norm の重みの細かさが約 5e-4 になる（int8 と float32 のファイルは float32 のまま）。
  - **q の行列は変換器が q と gate に分ける**（HF は head ごとに q 256 行・gate 256 行）。**並べ替えは RoPE の掛かる所だけ**: q と k の各 head の先頭 64 行（rotate_half の前半 32・後半 32 を隣どうしに）と、その head の norm の先頭 64 個。gate・v・linear の層は並べ替えない。変換の種類は `heads`（GPT-NeoX の `neox` を一般にしたもの: head の中の何番目の部分か、回す行数）・`one`（1 を足す）・`decay`（`−exp(A_log)`、GGUF の `ssm_a` と同じ）・`taps`（畳み込みの重みを「タップごとに 1 行」に）。知らない名前は今までどおり断る。
  - **BOS は文の終わりのトークン**（`<|endoftext|>` 248044）。0.8B の config は BOS を言わず、Qwen3.8 27B の config は bos と eos が同じ 248044。本物の使い方は BOS を置かない（T.131 と同じ扱い）。
- **前分割 `qwen35`**（結合文字 `\p{M}` を字の並びに入れる）: 文字の種類に結合文字の 1 字（`~`）を足し、ほかの 3 つの型は今までどおり「ほか」と同じに読む。本物の tokenizers と全符号位置で同じ（CI の全部の組、run 36876307564 の「the pre-tokenizers at every code point」5 件）。実物の Qwen3.5 の語彙（248,070 語片、追加のトークン 26 個）で 2,030 の文が本物と同じ ID。
