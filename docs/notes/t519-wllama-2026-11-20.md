# T519 wllama との速さの比べ（2026-11-20）

持ち主（2026-10-15）: 「比較してもいいけど製品のページに掲載する必要はないかなあ」。だから比べは試験の道具と CI だけで、数字はここと台帳にだけ書く（`/benchmark/` にもモデルのページにも載せない）。製品のコード（`src/`）は変えていない。前の調べは [t519-wllama-2026-10-15.md](t519-wllama-2026-10-15.md)。

## まとめ

- **同じ GGUF・同じ本数・greedy で、ページは wllama 3.13.0 の CPU より答えが 2.7〜5.4 倍、プロンプトが 3.0〜8.3 倍速い**（2 本、x86-64 の EPYC 9V74 と arm64 の GitHub のランナー）。1 本ではさらに開く（答え 4.6〜6.9 倍）。ページの relaxed SIMD を外しても（`?without=relaxed`）答え 2.6〜4.3 倍・プロンプト 3.5〜4.7 倍で、差の大半は relaxed でない。
- **準備完了は wllama のほうが速い**: 取得込みで 0.4〜0.8 倍の時間（変換が無い）、保存からの 2 回目も 0.5〜0.85 倍（ページは Pyodide の始まりの 2.7〜3.0 秒が大半）。
- **答えは同じ文から始まる**: PLaMo 3 Translate 2B は全文が同じ。SmolLM2 360M は 87 字（約 20 トークン）、Qwen3 0.6B は 204 字（約 40 トークン）まで同じで、その後で割れる（活性値の丸めがページは行ごとの int8、llama.cpp は 32 個ごとの Q8_0 で違う: 読み。どちらの答えも読める文）。
- **WebGPU は比べていない**: CI のランナーに GPU は無く、SwiftShader の速さは意味が無い（AGENTS.md）。wllama は既定で全部の層を WebGPU に置く。比べるなら持ち主の端末で（数字は未計測）。

## 道具（`tests/wllama_compare.py`・`tests/wllama-in-browser.ts`）

- `python tests/wllama_compare.py files`: 比べる 3 つのファイルの sha256 を huggingface.co に聞き、表の値と、wllama の例が名指すファイルと比べる。
- `python tests/wllama_compare.py run [model id …] [--rounds 5] [--tokens 128] [--threads 0] [--query without=relaxed] --results <file.jsonl>`: npm の `@wllama/wllama@3.13.0`（tarball の sha1 `2b8d7ce0b8b91b0d33a7c5bef1e847825bd65737`、llama.cpp `b12211-7d7f028`、git `6647c1ea`）を `.tmp/wllama/` に取り（sha1 を見る）、モデルごとに `tests/wllama-in-browser.ts` を 1 回。`table <file.jsonl …>` で表。要るもの: `npm run build`、playwright-core の Chromium、NumPy（`make kernels python` のため）。
- `wllama-in-browser.ts` は 1 つの Chromium（ディスクの profile）にページ（`dist/` を `tests/serving.ts` で）と wllama の小さな試験のページ（ブラウザの routing が `http://127.0.0.1:9/` に COOP・COEP 付きで答える: wllama のスレッドに要る。サーバは立てない: `serving-check`）を開き、(1) それぞれ取得込みで読み込み、(2) 読み込み直して保存から、(3) 1 回ずつ暖め（プロンプトの長さも知る）、(4) `rounds` 回ずつ交互に答えさせ、毎回順を裏返す（同じプロセス）。
- そろえたもの: greedy（ページは `temperature=0&repetition_penalty=1&presence_penalty=0`、wllama は `temperature: 0`）、CPU だけ（wllama は `n_gpu_layers: 0`、ブラウザに WebGPU は無い）、本数（既定は論理コアの半分 = wllama 自身の既定。ページは `?threads=`、取りまとめ役を含めて数える）、文脈 4096、wllama のプロンプトのキャッシュは切る（`cache_prompt: false`。`cache_n` が 0 でなければ落とす）、答えの長さ（ページの Max tokens はプロンプトも数える 16〜文脈の 8 刻みの滑り棒なので、プロンプト + 128 を切り上げ、wllama にも同じ数を頼む: 131）。
- 送る文: Qwen3 と PLaMo は wllama の素の completion にページの書式と同じ文（Qwen3 は一覧の BOS `<|endoftext|>` を文字で前に）。SmolLM2 は wllama の chat completion（GGUF の書式を llama.cpp の jinja で）。プロンプトのトークンの数はどれもページ + 1 = wllama で一致（ページの行は最後のトークンを数えない）。
- 速さはそれぞれ自身の数え: ページは答えの下の行（`generation.py` の `prompt_tokens_per_second`・`tokens_per_second`）、wllama は llama-server の `timings`（`prompt_per_second`・`predicted_per_second`）。表は 5 回の中央値。

## 読み（差の訳の候補、どれも確かめていない）

1. **カーネル**: 差の大半はここ（読み）。1 本でも 4.6〜6.9 倍、relaxed を外しても 2.6〜4.3 倍。wllama のプロンプトは答えの 1.3〜1.7 倍しか速くない（ページは 1.45〜2.6 倍）ので、llama.cpp の wasm の CPU の道は、まとめて読むプロンプトでも計算で詰まっている形に見える（ネイティブの llama.cpp が持つ重みの並べ替えと行列 × 行列のカーネルが wasm には無い、Q8_0 の活性値の 32 個ごとの float の尺度、Memory64 の番地の検査: どれも読んだだけで、wllama の wasm の中身は見ていない）。plamo-translate-desktop の README の値（Ryzen 9 9950X の CPU で毎秒 18 トークン、2B の Q4_K_M）は、本数が多い分を除けばここの 2.8〜3.0 と同じ桁。
2. **スレッド**: wllama は 1 本 → 2 本で 1.85〜1.9 倍、ページは 1.27〜1.53 倍。スレッドの分け方は wllama のほうが伸びる（ページの頭打ちはメモリ帯域と取りまとめ役: AGENTS.md の「スレッドで伸びるのは約 2 倍」）が、1 本の差が大きすぎて追いつかない。
3. **Python の費用**: ページは 1 トークンごとに Python を通るが、それを含めて速い。費用の比べにはならない。
4. **準備完了**: wllama が速いのは変換が無いから（GGUF をそのまま llama.cpp が読む）と、Pyodide の始まりが無いから。ページの方針（変換して int8 で持つ、Python で書く）から来るもので、取り込む形ではない。ただし PLaMo の取得と変換 27.6 秒のうち変換 14.2 秒は、速い回線では取得（wllama は同じファイルを 7.5 秒）より長い。

## 比べの条件の確かめ（レビュー、2026-11-21）

  1 本の SmolLM2: ネイティブ x86-64 103 / 37.0、wllama 6.2 / 4.7（答えは 7.9 倍遅い）。ページはネイティブの答えの 0.5〜0.8 倍、wllama は 0.14〜0.28 倍。ふつうの wasm の SIMD は、ネイティブの 0.3〜0.5 倍が目安（読み。公開の測りは見ていない）で、ページはそこにいる。**wllama はそこから 2〜3 倍外れる**。ネイティブとランナーの CPU は同じ run のものでない（ネイティブ x86-64 は EPYC 7763、ブラウザの run は 9V74）ので、比は粗い。

## 確かめたことと、読んだだけのこと

- 確かめた: 3 つのファイルの sha256（huggingface.co の `x-linked-etag`）、wllama の npm の tarball の sha1、両方が同じ数のプロンプトのトークンを読むこと、答えの頭が同じこと、wllama が 2 本の回で `isMultithread()` 真・`crossOriginIsolated` 真・`n_batch` 2048・`n_ubatch` 512、プロンプトのキャッシュを使っていないこと、保存からの 2 回目に wllama が取り直していないこと。
- 読んだだけ・未計測: 差の訳（上の「読み」）、WebGPU、持ち主の端末（Android の Chrome）での比、wllama の互換の版（Firefox・Safari）、本数を 4 にした回、長い文脈での比。
