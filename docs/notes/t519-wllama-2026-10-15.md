# T.519 wllama から取り込める設計を見る（2026-10-15）

調べと表だけ。製品のコードは変えていない。相手のリポジトリ https://github.com/ngxson/wllama を浅く clone して（submodule の llama.cpp は取っていない）、TypeScript・C++ の糊・ビルドの設定・試験・デモ（`examples/main`）を読んだ。Hugging Face の Space https://huggingface.co/spaces/ngxson/wllama は API でファイルの一覧と `README.md`・`build.sh` を読んだ（走らせていない）。npm と jsDelivr は API で版とファイルを見た。

## まとめ

- **wllama は llama.cpp の `llama-server` の推論の部分（`server-context.cpp`）を丸ごと wasm にして、OpenAI の形の API で包んだもの**（3.11.0、llama.cpp `b11557-5c8854f`）。チャットの書式・標本抽出・道具の呼び出し・画像の入力は llama.cpp の中で動き、TypeScript の側は取得・保存・Worker・型だけ。
- **取得・保存・メモリ・スレッドのどれも、pyodide-llm のほうがもう先にいる**: wllama はファイルを丸ごと 1 本ずつ取り（並べるのは分けたファイルの 3 本まで、取り直しなし、Range なし）、メモリは 64 ビットの版でも最大 4 GB、スレッドの本数は論理コアの半分に固定。pyodide-llm は Range の部品を並べて取り直し、16 GiB まで置き、本数を端末で測る。
- **分けた GGUF（`-00001-of-0000N.gguf`）を開く工夫は、ここでは効かない**: wllama がそれを要るのは 2 GB の `ArrayBuffer` と 4 GB のメモリの壁のため。pyodide-llm は 1 本のファイルを Range で並べて取り、変換しながら置くので、その壁が無い。ダウンロード上位 500 の GGUF のリポジトリで、ここが開ける形と大きさなのに Q8_0 が分けたファイルにしか無いのは 1 つ（`Qwen/Qwen2.5-7B-Instruct-GGUF`、T.74 で避けると決めた公式の GGUF）。
- 取り込む値があるのは 2 つ: **(1) 同じファイルで速さを比べる**（T.95 が未着手のまま。SmolLM2 360M Instruct の Q8_0 は wllama のデモとここの一覧で sha256 まで同じファイル）と、**(2) 考える形の答えの「考えの上限」と「考えを畳む」**（wllama が llama.cpp に渡す `reasoning_budget_tokens`・`reasoning_format`。ここのページは `<think>` の中身をそのまま書く）。

## 4. 速さの手掛かり

- **wllama の公表の tok/s は見つからなかった**: リポジトリの README・`guides/`・デモに数字は無い（デモの `benchmark.ts` は中身をコメントにして「not ready yet」と投げる）。WebGPU の紹介のブログ（https://reeselevine.github.io/llamas-on-the-web/）はその場で CPU と WebGPU を測るベンチを持つだけで、本文に数字は無い（束ねた JS の中の文を見た）。
- **ここの台帳の同じモデル**: Qwen3 0.6B（すぐ答える形）は本番 27.6 tok/s（Chromium 156、EPYC 7763 の 4 論理コア、4 本、run 38726654593: T.511.5 の表）。SmolLM2 360M は本番 47.2 tok/s（run 36889454702、2026-10-01: TASKS.md の頭の「本線（3881b9a）の確かめ」の行。ランナーと本数は書いていない）。
- **比べで見るべき差（読んだだけ・未計測）**: (1) wllama の既定はすべての層を WebGPU に置く（`n_gpu_layers` 99999）ので、CPU と比べるには `n_gpu_layers: 0` を渡す。(2) wllama の本数は論理コアの半分（4 論理コアのランナーで 2 本）、ここは測って選ぶ: 本数をそろえた行と、それぞれの既定の行を並べる。(3) wllama のプロンプトは `n_batch`（デモ 128）でまとめて通す。ここは 16 トークンのブロック（T.108）。(4) wllama の既定の版は JSPI と Memory64 が要る（Chromium）。Firefox と WebKit では互換の版になり、遅いと wllama 自身が言う（「Performance will be significantly degraded」）。
- **T.95 の結果を書き直す材料**: T.95 は未着手で、結果はまだ無い。書き直すのは手順のほう: (a) wllama は v3 で API が変わった（`loadModelFromUrl`・`createChatCompletion`、標本抽出は頼みごと）、(b) 比べるファイルは T.95 が挙げた SmolLM2-135M より、**sha256 まで同じと確かめた SmolLM2 360M Q8_0** と、wllama のデモにもある Qwen3 0.6B Q8_0 が良い、(c) WebGPU の行を足す（T.95 の頃の wllama には無かった）、(d) 版は npm の最新（いま 3.8.1）を実行時に解決する。
