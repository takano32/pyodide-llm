## モデルの形（transformers 5.16.1 の `models/phi3`）

Llama の層に 2 つの違い: (1) q・k・v が 1 つの行列 `self_attn.qkv_proj`（q の行、k の行、v の行の順）、(2) FFN の gate と up が 1 つの行列 `mlp.gate_up_proj`（`chunk(2)`: gate が先）。RoPE は `rotate_half` を頭の最初の `partial_rotary_factor` の分だけ（Phi-3 mini は 1.0、Phi-4 mini は 0.75: 頭 128 のうち 96）。config.json に `sliding_window` があれば transformers は窓の mask を掛ける（Phi-3 mini 4k は 2047、Phi-4 mini は 262144）。

変換器: 家族 `phi3`（`convert/families/phi3.py`）。行列は段 `rows` で割り（PLaMo 3 と同じ）、q と k は段 `heads` で回す行だけ並べ替える（Qwen3.5 と同じ。頭の全部を回すなら Llama の `permute` と同じ）。文脈は窓に切る（Mistral v0.1 と同じ扱い: Phi-3 mini 4k の文脈は 2047）。GGUF は読まない（llama.cpp の phi3 は `attn_qkv` と `ffn_up` を 1 つのまま、longrope の倍率を `rope_factors_*` のテンソルで持つ）。

エンジン: アーキテクチャ `phi3` = `LAYOUTS["llama"]._replace(rope=PARTLY)`。新しい事実もカーネルもシェーダも無い。回す割合の表（`partial_tables()`）に Llama と同じく倍率を載せるようにした（T258.2 の longrope の attention factor のため。今ある PARTLY の 3 つは倍率を持たないので変わらない）。int8 のファイルは Phi-3 mini で 4,299,288,604 バイト（4 GiB を少し越える: 64 ビットのメモリのブラウザ）。

## added tokens の `rstrip`・`lstrip`

Phi-3 mini の tokenizer.json の added tokens は `</s>` と 32001〜32010（`<|assistant|>`・`<|system|>`・`<|end|>`・`<|user|>`・placeholder）が `rstrip: true`、Phi-4 mini は 200019〜200028 の 10 個（`<|assistant|>`・`<|end|>`・`<|user|>`・`<|system|>`・`<|tag|>`、special でない `<|tool|>` など 5 つ）が `rstrip: true`。本物（tokenizers 0.23.3）は印の右の空白を印に含める: Phi-3 の書式 `<|user|>\nHello<|end|>\n<|assistant|>\n` は `[32010, 15043, 32007, 32001]`。

- エンジン: トークナイザの設定 `stripped`（`{"right": [...], "left": [...]}`）。`encode()` が specials で切った後、右を食う印の後ろの文の頭と、左を食う印の前の文の尻から空白を落とす。空白は Unicode の White_Space（本物の `char::is_whitespace`: Python の `isspace` から \x1c〜\x1f を除いた 25 字。`tests/test_stripped.py` が全符号位置で本物と比べる）。
- 書式の頭の印を BOS にしたモデル（どちらの Phi も `<|user|>` が BOS）は、書式の残りが BOS の後ろから始まる。`generate()` が BOS を `encode(prompt, specials, after=bos)` に渡し、BOS が右を食う印なら頭の空白を落とす（問いの頭の空白も、本物と同じく食われる）。
- 変換器: tokenizer.json の added tokens のうち `rstrip` か `lstrip` の立つものだけを言う（`convert/vocabulary.py` の `stripping()`）。立つものの無い tokenizer.json の options は変わらない。
- `tests/tokenizer_json_check.py --planes 17`（変換器と同じく `stripping()` を足して）: Phi-4 mini 2,333,447 文で 0 wrong（T256 では added tokens を入れた文で 2,987 wrong）。

## longrope（Phi-4 mini、T258.2）

transformers 5.16.1 の `_compute_longrope_parameters` と `longrope_frequency_update`: 角は `1 / (ext_factors * base^(2i/d))`、`ext_factors` は文（`max(position_ids) + 1`）が元の文脈（`original_max_position_embeddings`: Phi3Config では config.json の最上位の欄が scaling の中のものに勝つ）以下なら `short_factor`、越えれば `long_factor`（その時は文の全部をそれで回す）。attention factor は scaling に無ければ `factor`（無ければ文脈 ÷ 元の文脈）から `sqrt(1 + ln(factor) / ln(original))`、文の長さに依らず cos と sin に掛かる。

Phi-4 mini: `short_factor` は 48 個とも 1.0、`long_factor` は 1〜47.77、文脈 131072 ÷ 元の 4096 = 32 で attention factor は sqrt(17/12) = 1.1902（score は 1.417 倍鋭い）。**短い因子が全部 1 でも素の RoPE ではない**。

- エンジン: `rope_frequencies()` に longrope（短い因子で割る。数が回す対の数と違えば断る）、`rope_magnitude()` に attention factor。
- 変換器: 家族 `phi3` の `after`（`phi3_longrope()`）が文脈を元の文脈に切り（長い因子は使われない）、scaling を `{rope_type, short_factor, attention_factor, original_max_position_embeddings}` にする（2 回目は 1 回目の attention factor を残す）。検査は家族の `check`（短い因子が対ごとに 1 つ・どれも正、attention factor が正）。longrope を受ける家族は `Family.scalings`（Llama の config.json の longrope は今までどおり断る）。
- 一覧の options の `rope_scaling` に 48 個の数の並びが入る。ページの道（Pyodide の JsProxy）は smoke が通す。
