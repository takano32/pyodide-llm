## モデルの形（transformers 5.16.1 の `models/bitnet`）

Llama の層に 3 つ: (1) wo の前の RMSNorm `attn_sub_norm`（attention の幅）、(2) w2 の前の RMSNorm `ffn_sub_norm`（hidden_dim）、(3) gate の活性化が ReLU の 2 乗（`relu2`）。GQA（20 head、鍵と値は 5）、RoPE は head 全体（theta 500000）、分類器は埋め込みと共有。

エンジン: アーキテクチャ `bitnet`（`LAYOUTS["llama"]._replace(rows=bitnet, activation=RELU2)`、行 `rms_att_sub_weight`・`rms_ffn_sub_weight`）、カーネル `reglu2`（4 つずつと 1 つずつがビット単位で同じ、NumPy の `relu2()` とも同じ）。GPU には置かない（活性化が SiLU・GELU でない: 今ある訳 `REASONS.pair`。GPU だけも `aloneActivation`。2 つの norm は `extras` でも断る）。

変換器: 家族 `bitnet`（`convert/families/bitnet.py`）。行列は U8 の読み手（`SOURCES["U8"]`、ggml の型ではない）→ 段 `("planes",)`（4 分の 1 ずつの行を 2 ビットずつ戻す: transformers の `unpack_weights()` の形）→ 段 `("by", 名前)`（ほかのテンソルの 1 値を掛ける。`resolved()` が読んだ値を入れる）→ q と k は Llama の並べ替え。形の `kinds` で 7 つの行列を `ternary` にする（値が −1・0・1 × 1 つの scale なので、どの dtype のファイルでも損なし）。埋め込みはファイルの dtype（一覧の項目は int8）。**scale は行列より前に読む**: 公開のファイルは浮動小数のテンソルが全部 U8 より前にある。ページの Stream は scale が後ろにあるファイルを断る（ビルドの `convert_weights()` はどこにあっても読む）。**scale は float16 に入る値でないと 3 値の dtype が断る**（公開のものは層 0 と層 29 の 14 個で 0.95〜2.83、どれも bfloat16 なので入る）。

## 活性値の丸め

モデルは行列が読む値を、トークンの最大値で 8 ビットに丸める（transformers の `ActQuant`: 1 トークンに 1 つの尺度）。エンジンはそうしない: NumPy の forward は浮動小数、ページのカーネルは 32 ずつの群で丸める（int8 と 3 値のモデルの全部と同じ）。作り物（`tests/test_bitnet.py`）では、モデル自身の丸めが logits を最大の logit の約 2% 動かし、32 ずつの丸めは約 0.9%（どちらも浮動小数の参照から）。実物での差は CI の `tests/reference_bitnet.py` が言う（下）。

## transformers との比べ（`tests/reference_bitnet.py`、CI run 43273378462、AMD EPYC 9V45）

- **最初の run 43262511808 はランナーを失った**（52 分、「The hosted runner lost communication」: ログなし）。transformers の 2B を float32 で広げたもの（約 10 GB）と、エンジンの NumPy の広げた行列（約 9 GB）を 1 つのプロセスで持った。いまは実物の部分を段ごとのプロセス（`--phase=transformers|float32|int8`）に分け、数をファイルで渡す。チェックポイントは mmap で読む。
- 作り物（5 つ）: 浮動小数では、単体試験の参照とエンジンがどちらも transformers から 1e-5 以内。丸めた形（ActQuant）では、256 段の境にある値が和の順でどちらにも転ぶ。transformers 自身の 2 つの道が 4.85e-2 離れ、参照は別の作り物で 0.17 離れた（最初の run 43271958650）。だから丸めた形は平均の差で見る: 丸めが transformers を動かす量の 10 分の 1 以下で、最尤のトークンが全部同じ。通った。
- 実物（96 位置）: transformers の 2 つの道の差は浮動小数で 3.81e-5。エンジン（float32 のファイル）は浮動小数の transformers と最大 3.81e-5、最尤 96/96。壊し方 6 つはどれも線の 918 倍以上で、いちばん弱いのは層 15 の wo の scale を 1.25 倍にしたもの。
- **丸めの差**: transformers を丸めた形と丸めない形で比べると、最大 1.63、平均 0.247、最尤 94/96。ページの道（int8 のファイル、32 ずつの丸め）は浮動小数の transformers と最大 0.195、平均 0.0154、最尤 96/96、丸めた transformers と平均 0.248。**ページはモデル自身の丸めより、丸めない計算に 16 倍近い**。greedy は 3 つとも「The capital of Japan is Tokyo.」（transformers の generate は止まりで止まるので、16 トークンの一致は 8）。
