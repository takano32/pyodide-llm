### トークナイザ

- **`encode()` を速く（T200・T207・T222）。** BPE は対を heap に入れ、合併した所の両隣だけ入れ直す（`merged()`: byte-level BPE も前分割の語ごとに同じ輪で、T639.4。点数の線だけが違い、`bpe` は −1e10（llama2.c の）より上、`bytebpe` は `UNMATCHABLE`（−1e8）より上を合わせる: 変換器の −1e9 の語片は `bpe` では合わさり、`bytebpe` では合わさらない）。unigram は語片を辞書で引き、試す長さを `reach` まで。前分割は文字を種類の 1 字に `str.translate` で写して標準の `re` で型を走らせる（`CharClasses`）。全符号位置を本物と比べる試験は `EVERY_CODE_POINT=1`（全部の組だけ）。
- **前分割の文字の種類を本物に合わせた（T206）。** \x1c〜\x1f は空白でない、ſ（U+017F）は `(?i:'s)` で s と読む、`gpt2-digits` の数は `\p{N}`。Python の Unicode が割り当てていない文字は比べから外す。速くした代わりに unigram のコンストラクタが 11〜38 ms 遅く、Pyodide の持つ量が増えた（llm-jp-3 150M で 9.1 → 15.2 MiB）。
- **語彙に無いバイトは落とす**（SmolLM2 の語彙は 1 バイトの語片が 21 無い。本物と同じく語に入れない）。
- **sentencepiece の正規化は model の charsmap そのもので（T216）。** 変換器が `precompiled_charsmap` を tokenizer.bin の後ろに付け、エンジンの `Charsmap` が double array をそのまま辿る。文の中の U+2581「▁」は空白（byte-level BPE を除く）。バイトの語片が無い語彙（rinna）は `collapse`・`unknown`。
- **sentencepiece の BPE を書き出した tokenizer.json（T257: Gemma 3・Gemma 4・CAT-Translate 7B）。** normalizer が「空白を ▁」だけ・前分割が無いか Gemma の `Split(" ")`・`byte_fallback` とバイトの語片 256 のもの（`written_out()`）。**tokenizer.bin の形式は同じ**: 語片の点数に「その語片を作る最初の merge の順位 × −1」。`byte_fallback` とバイトの語片は 256 の全部が要るが、ASCII のバイトでその字そのものが語片にあるものは欠けてよい（T612.2: Gemma 2 の語彙は `<0x09>` を持たず、タブは語片 226。エンジンはその字を語片で読むのでバイトでは綴らない）。変換器が「語片を 2 つの語片に割る割り方は全部 merge」を確かめ、破れていれば断る（`merged_by_text()`）。**同じ点数の語片が並んで 1 つの語片の merge が離れると、エンジン（語片の最初の順位）と merges（対の順位）の読みが違いうる**: `read_otherwise()` が、ほかの語片の最初の merge より後の merge と、それと 1 つの語片を分け合う隣の merge の 3 語片の文を両方の読みで合わせ、違えば同じ文で断る（T509: 点数を 4 個ずつ同じにした作り物は断り、Gemma の同じ点数の改行・空白・タブの並び 87 語片は通る。3 語片の文がどれも合い、4 語片以上の文でだけ違う語彙は見逃しうる（レビューの乱数の語彙で 150 通りのうち 8 通り。実物では起きていない）。Gemma 4 でネイティブ約 0.9 秒、Pyodide の中で約 1.6 秒）。モデルの行の無い追加のトークンは落とす（`with_a_row()`: 文字だけの Gemma 3 の `<image_soft_token>`）が、それが BOS・止まり・書式の書くトークンなら断る（T509、`beginning_and_stops()`）。**段取りは、ダミーの空白を持つ形だけをほかの候補の後に回す**（`Later`: `tokenizer.model` があればそれを読む）。Pyodide の中の変換はヒープを約 255 MiB 伸ばす（33 MB の JSON）。実物 3 つは全符号位置を含む各 234 万文で `tokenizers` と同じ ID（**この読み手に触ったら `tests/tokenizer_json_check.py --planes 17` を手で**）。理屈の上の残る違いは docs/notes/t257-spelled-bpe-2026-10-14.md。GGUF の語彙（`add_space_prefix: false`）は今も断る。
- **PLaMo の `tokenizer.jsonl`（T649.1）。** 1 行に [語片, 点数, 種類]。変換器の読み手は `convert/vocabulary.py` の `plamo()`（名前が `.jsonl` で終わるファイル）、エンジンの種類は `plamo`（tokenizer.bin の形式は同じ: 点数は float32 のまま、BYTE の語片は `UNMATCHABLE`）。本物（`tokenization_plamo.py` の Aho–Corasick と Viterbi: 形だけを取った）との違いの要は 3 つ: (1) **点数は `round(score·1e4)` の整数で足す**（float32 の和では同点の並びが変わる。点数は小数 4 桁までで、float32 から同じ整数に戻ることを変換器が確かめる）。(2) **同点は最初の語片が長いほう**（本物は文の後ろから探す。unigram の道は前から探して最後の語片が長いほうを取るので、unigram に options を足す形では合わない）。(3) **語片の無い字は 1 字 1e7** で UTF-8 のバイトの語片に。探す前に `<|plamo:…|>`（語彙に無い名前も）と、options の `breaks`（tokenizer_config.json の `break_around_repeated_chars_threshold`・`break_around_consecutive_spaces_threshold`: 4 回以上の同じ字・2 つ以上の空白）の前後で切る。本物は切れ目に U+EE00 を書いて後で落とすので、文の中の U+EE00 も消える。CONTROL の語片は点数 0 の語片として探索が見つけ、`<|plamo:…|>` の形のものだけが specials（`<|plamo:begin_` のように形の違う 3 つは探索に任せる）。ダミーの空白も正規化も無く、空白は空白のまま。**本物の道具を numba 抜きの素の Python で回さない**（NumPy の真偽値の和は真偽値で、3 バイトの未知の字を 2 バイトと数えて落ちる）。0.8B・2B・8B の `tokenizer.jsonl`・`tokenization_plamo.py`・`tokenizer_config.json` は sha256 で同じ。
- **Mistral の Tekken（T611、`tekken`）。** Mistral Nemo の前分割は Split 1 つで、字の大文字・小文字を見分ける（`[\p{Lu}\p{Lt}\p{Lm}\p{Lo}\p{M}]*[\p{Ll}\p{Lm}\p{Lo}\p{M}]+` の形: 「HelloWorld」は「Hello」「World」、「/」は記号の後ろに付く）。字の種類の表 `TekkenClasses`（大文字と title case・小文字・どちらでもない字（Lm・Lo）・印・数・`/`）の上で `STAGES` の 1 段。`ignore_merges` は真、normalizer は無い。GGUF の `tekken` は実物 2 つ（QuantFactory の Mistral-Nemo-Japanese と mradermacher の shisa-v2-mistral-nemo の Q8_0）の語彙と merges を原本と突き合わせた（どれも同じ順で同じ）。
- **置き換え（options の `replaced`、T617）。** 語彙に無い文字（改行）をカードが別の文字列（`<NL>`）で書くモデルのために、`Tokenizer` が encode の頭（正規化と specials の前）で `(書く文, 読む文)` を置き換え、`generate()` が出る文を逆に戻す（`engine/tokenizer.py` の `Unreplaced`）。**読む文が何トークンにも割れる**（rinna の spiece.model では `<NL>` は `<`・`N`・`L`・`>` の 4 語片）ので、出る文の終わりが読む文の頭になりうる間は持っておき、次の文か終わり（`final`）で出す。置き換えの無いモデルでは `generate()` は何も呼ばない（`Unreplaced` を作らない）。戻すのは出す文（`echo` のプロンプトか引いた語）だけで、出さないプロンプトの文は通さない。
- **special でない追加のトークンも specials に（T143）。** 本物は前分割の前にどこでも 1 つに読む。並びは長い順・同じ長さは文字の順。specials の多いモデル（Gemma 3 の 6,406 個）は切り分けの型を組ごとに 1 回だけ作る（`Tokenizer.cut()`）。
