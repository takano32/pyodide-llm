# HF からの取得と変換

AGENTS.md の「これまでに分かったこと」節から移した（T658、2026-11-12）。要点は AGENTS.md に。

計測環境: 2026-09-26 までの「この開発機」は ARM big.LITTLE（Cortex-A78×4 + A55×4）、メモリ約 6.6GB・スワップなし。2026-09-26 からは a1-free（OCI の Ampere A1、Neoverse-N1 × 2、メモリ 11.9GB・スワップ 4GB、Ubuntu 26.04.1）。どちらも Node 24。**変更の前後を 2 つの機械の数字で比べない**。モデルごとの数字の表・run の ID は `docs/tasks/T番号.md` と `docs/notes/` にある。

### HF からの取得と変換

- **HF から取得してブラウザの中で変換する（T60）。** HF は CORS を許可し Range に 206 で応える。日本からは 1 回の要求に 1〜3 秒かかるので、**変換器はファイルの順に受け取る**（`Stream`）。読めるのは、Llama 構造（RoPE の縮めは llama3・linear・yarn。Mistral と Granite 4.2 は Llama として読む）・Qwen2・Qwen3・Qwen3.5・LFM2・Gemma 2・Gemma 3・Gemma 4・Spark・PLaMo 3・GPT-2・GPT-NeoX、safetensors（分割も）か GGUF（Q8_0・3 値・1 ビットの Q1_0・K / i 量子化の塊）、Unigram か byte-level BPE か sentencepiece の BPE を書き出した形の `tokenizer.json` か sentencepiece のモデル。
- **取得は部品の大きさで決まる（T107）、上限の低い回線では効かない（T136）。** **最初の部品は 8 MiB で、その速さで残りを決める**（4 MB/s 以上で `deviceMemory` が 4 より大きければ 16 MiB）。米国の CI では 4 MiB 23 秒・8 MiB 11.3 秒・16 MiB 8.3 秒。並列数はほとんど効かない。日本の家の回線は 7.1〜9.4 MB/s（回線の上限）。HF は日本からも米国の CDN に 302 で振り向け、署名つきの URL は約 1 時間で切れる。
- **変換は速く、律速は取得（T89・T123）。** 量子化はカーネル `quantize_x`（NumPy とバイト単位で同じ）、bf16・Q8_0・3 値の広げもカーネル（`widen_*`）、relaxed の補正は `int8_sums`。変換器には `readers` の 1 つで渡し、`kernel_readers(カーネルのパス)` が登録簿のカーネルのある型を全部作る。変換のスレッド化は取りやめた。
- **byte-level BPE（T63）。** HF は「順位がいちばん小さい merge」、エンジンは「スコア最大の対」なので、**スコアに −順位を書けば同じ結果**（`tokenizer.bin` の形式は変えずに済んだ）。前分割は手書きで、知っている型だけを受け付ける。
- **小さな違いだけの家族**: Qwen2 は q・k・v の bias（層ごとにファイルの末尾へ足し、ヘッダはそのまま。有無はファイルから分からないので設定で渡す。**bias も wq・wk と同じ並べ替えが要る**）。HF の GPT-2 の都合: `transformer.` が付くモデルと付かないモデル、`gelu_fast` は `gelu_new` と同じ。**回転の並べ替えは q と k だけ**。GPT-2（LayerNorm・GELU・学習済みの位置の表・Conv1D で転置・`c_attn` 1 つ）と GPT-NeoX（head の先頭 `rotary_pct` だけ回す・並列残差）は別の forward を増やさずオプションで。**ファイルから分からない設定は、変換器が渡す経路もテストする**（`Conversion.options`）。Llama 3 系は RoPE の llama3 方式・前分割 `llama3`・`ignore_merges`。**RoPE の表を作る式は `rope_frequencies()` の 1 か所だけ**（llama.cpp の `rope_freqs` と相対 2e-7）。Mistral は `normalize()` が llama に読み替える（`"head_dim": null` は「無い」）。
- **Qwen3（T124）**: **head ごとの q・k の RMSNorm**（`qk_norm`）と **dim / heads と違う head の大きさ**（`head_dim`）。どちらもそのモデルのときだけ options に載る。**`footprint()` には形を渡す**（渡さないと KV を 45% 少なく数える）。**RMSNorm の eps はモデルのものを使う**（カーネルの `rmsnorm` が eps を受け取る。1e-5 でないときだけ options に）。**書式**: 考える形は本物の書式、すぐ答える形は空の `<think>\n\n</think>\n\n` を手で書く。`<think>`・`</think>` は special でない追加のトークンで `specials` に入る。
- **chat_template の読み方（`convert/template.py` の `rendered()`）。** jinja2 だけで、transformers の `apply_chat_template` と同じ環境で描く（NumPy と同じ扱いの依存: jinja2 を import できない変換器は、書式を読む所で `ImportError` を投げ、書式なしで黙って続けない。自前の Jinja の読み手は T640.14 で消した）。1 ターンぶんだけ描いて `{prompt}`・`{prompt:trim}`・`{date:書式}` の形に戻す（`one_turn()`。`{date:…}` はページの `filled()` が訪問者の今日で埋める）。`src/models.ts` の `template` が優先。worker は変換するときに `loadPackage("jinja2")` を頼み、NumPy と同じ扱いで待つ（`worker/pyodide.ts` の `templatePackage()`: Pyodide の段 `stepOf()` の 1 つで、版は Pyodide の lock のもの、ステータス行には出さない。30 秒何も届かなければ NumPy と同じ失敗（種類 `runtime`、`Pyodide <版>: "jinja2" got nothing from the network for 30 seconds`）で変換が止まる: 方針 2。`converter(signal, true)` の変換だけが頼み、保存した変換を読むだけの訪問・語彙を読むだけの翻訳・保存した塊を広げるだけの読み込みは頼まない）。jinja2 の import は書式を最初に読むときに 1 回（Node の Pyodide で環境を作るのに約 0.3〜0.45 秒、wheel は 145 KB）。トークナイザの名指さないトークン（空の `pad_token`）は jinja2 に渡さない（`x is defined` が変わる）。`tokenizer.model` のときは CONTROL の語片を特殊トークンとして渡す。`chat_template.jinja` は `tokenizer_config.json` に書式が無いときだけ取る。**書式の読み方に触ったら `tests/template_corpus.py`**（Hub の上位 500 リポジトリで違う文を書くものは 0）。
- **大きいモデル。** 分割された safetensors は見出しを 1 本にまとめる（`joined_shards()`）。本番の Chromium（4 本）で 3B 級は 7.5〜8.1 tok/s、7〜8B は 3.4〜3.9 tok/s・ヒープ 9.7〜11.0GB。
- **GGUF を取り込み元に（T74・T136）。** GGUF のテンソル表を safetensors 風の見出しに見せる別の source で、`Stream` をそのまま使う。**Q8_0 は損なく int8 に戻る**。**GGUF を足すときは必ず `gguf_check.py tensors` を先に通す。作り手ではなく 1 つずつ**（作り手が bf16 にする前の重みから GGUF を作っていれば「原本は GGUF の bfloat16」の読みで通す: T307）。llama.cpp の書き方: Llama の q・k は回して入っている（Qwen2・Qwen3・Gemma・Spark は HF の並び）、GPT-2 の Conv1D は転置、NeoX の `query_key_value` は [q; k; v] に並べ替え（2023 年の古い GGUF は HF の並びのままで、使わない）、語彙は詰め物で埋まる、Llama 3 の RoPE の縮めは `rope_freqs` の表（`Stream` が流れの中で比べる）。
  - **段 ②: 語彙・config・書式は原本のリポジトリ（`hf.vocabulary`）から、重みだけ GGUF から**。`gguf_agrees()` がテンソルの形で分からない数を config と突き合わせる。**ページの `?hf=` とシートは GGUF も開く。フォルダは safetensors だけ**。
  - **一覧に無いリポジトリの入口（`src/page/repository.ts`）。** ページは読み込みの前に HF の API（`/api/models/{repo}/tree/{revision}`: CORS は 3 つのエンジンで通る）にファイルの一覧を聞く（1,000 項目を越える一覧はページに分かれ、`Link` の「next」をたどる: `PAGES` 10 まで、全部で 10 秒。丸ごと取れない一覧（後のページの失敗・上限・ほかのホストの次のページ）は無いのと同じ: 名指しのまま開く。部分の一覧では「無い」と言いうる。T508.1）。`model.safetensors` か index があれば safetensors。無ければ読める GGUF のいちばん上（`QUANTIZATIONS`: 持ち主の順 Q8_0 → Q6_K → Q5_K_M → Q4_K_M、float と 3 値は Q8_0 のすぐ後ろ、4 ビット未満は最後。分かれた部品・`mmproj`・`imatrix`・フォルダの下は選ばない）。それも無ければ持ち主の文「{repo} has no model.safetensors and no GGUF file this page can read.」。`&file=` が名指せばそのファイル（`address.ts` の `FILE`）。**段取りには何も足していない**（worker に渡るのは今までの `hf`）。選んだファイルは URL の `&file=` に書く。
  - **GGUF だけの変換（`Conversion.from_gguf()`、docs/notes/t505-gguf-alone-2026-10-13.md）**: 分かる所は読み、分からない所は前と同じ文で断る。(1) BOS を言わない GGUF は、書式が読めてその頭が 1 つのトークンのときだけ開く。EOS を言わない GGUF は断る。(2) `rope_freqs` の表は頭のバイトから読み、`llama3_scaling()` が設定に読み戻して作り直した表が合うときだけ開く（最初のテンソルでない表は断る）。(3) 語彙は表 `GGUF_VOCABULARIES`: `gpt2` と、点数が sentencepiece の BPE の形の `llama`。点数の無い語彙と Unigram の点数は断る。(4) **前分割の名前は、実物の GGUF と原本の `tokenizer.json` を突き合わせたものだけを `GGUF_PRETOKENIZERS` に**（`GGUF_NFC`・`GGUF_IGNORE_MERGES`）。**GGUF の中の書式は原本と違うことがある**（作り手が直したもの・古いもの: GGUF だけで開けば GGUF の書式に従う）。ダミーの空白は最初の文にだけ（llama.cpp は特殊トークンの後にも置く: 実物の Mistral v0.3 で原本と合わなかった）。GGUF だけの道の断り: `tokenizer.ggml.pre` を書かない byte-level BPE は「This GGUF splits text as default, …」、`precompiled_charsmap` が空でない sentencepiece は語彙の文。見つけた GGUF の大きさは項目の `download`（シートから開くと 500 MB から確かめる）。保存の名前は、id が `local` で `model.safetensors` でないファイルのときだけ `リポジトリ@リビジョン/ファイル`。
  - 取り込み元が変わると保存の名前が変わる。Worker は新しい保存の前に同じ項目の古い名前の保存を消す（`replaced()`）。1 つの変換を分け合う項目は `shares` に両方の id。**保存の名前は取り込み元から作り、項目の id を読まない**（`keptName()`）ので、`shares` の 2 つの項目は 1 つの保存を読み合う（T649.5: もう一方を選ぶと保存から準備完了する。manifest の `id` は変換した項目のもので、`replaced()` とページの消すボタンは `shares` の id の全部で見る。書式・`bos`・止まりは項目の options と `template` が保存の options に勝つ）。`tests/e2e.ts` の `E2E_THEN` が、最初のモデルと `shares` を分け合う項目を保存から読んだかを見る。
- **頭のトークン（BOS）・止まり・書式（T369 の回 = `CONVERTER` 10）。** エンジンはどの文も options の `bos` から始める。規則は「**書式を読めたモデルは、本物の `apply_chat_template` と同じ ID を送る**」（持ち主、2026-10-10）。変換器は 1 ターンを描いた文の頭を見る（`convert/beginning.py` の `turn_head()`）: (1) トークナイザの BOS で始まるならそれが `bos`。(2) 別の「1 つに読まれるトークン」（`<|im_start|>`）で始まるなら、それが `bos` で書式はその次から。(3) 文字で始まるなら BOS が前。**(2) をしない場合**: sentencepiece 系は最初の文にだけダミーの空白を付けるので、頭のトークンを外すと次の文の読みが変わる（外すのは byte-level BPE、`prefixed` が `"every"` か `"never"`、次が書式の文かトークンのときだけ）。
  - **止まり**は、モデルのファイルが「答えの終わり」と言うもの: BOS・config.json の `eos_token_id`・トークナイザの `eos_token`。**頭のトークンは止まりに入れない**（harmony の llm-jp-4 は考えの後に `<|end|><|start|>assistant…` と書いてから答える）。BOS がどこにも名指しされていないモデルは当て推量の 1 を止まりに入れない。**書式が答えの後に書くトークンも止まり**（`convert/template.py` の `answer_end()`: 会話を答えで終える形を描き、答えのすぐ後の「1 つに読まれるトークン」。Gemma 4 の `<turn|>`）。`generation_config.json` は取っていない。
  - **`bos` と `template` は組**。T369 の前に片方だけを任せていた 21 項目は、送る ID を変えないために前の `bos`・止まり・書式を書いてある（`formats.js` の `QWEN3_OWN_BOS`・`QWEN25` など。寄せるのは T399）。**変換器の `bos` か書式の出し方を変えるときは `tests/conversions_compare.py` で全項目の送る ID を前後で比べる**（`format_check.py` は BOS が 1 つ多くても通す）。
  - **モデルごとの BOS は `start_check` で測って項目の options に**: DeepSeek-R1 Distill は tokenizer_config の `bos_token`、**Qwen3 の 8B 系は前に `<|endoftext|>` を置くと +54〜144%**（4B 以下は 5% 以内）、Qwen3.5 も大きく効く、LINE japanese-large-lm は大きさで向きが逆。
  - **トークナイザの言うことを読む**: `do_lower_case`（sentencepiece の道の tokenizer_config.json か、tokenizer.json の normalizer の `Lowercase`）は options の `lowercase`。**特殊トークンの後のダミーの空白は options の `prefixed`**（無ければ最初の文にだけ。`"every"` は特殊トークンの後のどの文にも: normalizer の `Prepend("▁")`。`"wanting"` は空白で始まらない文にだけ: `prepend_scheme: "always"` か legacy の `LlamaTokenizer`。`"never"` はどの文の前にも付けない: Gemma と `add_dummy_prefix: false`）。**2 つは別の物**（`tests/test_prefixed.py`）。**最初の文の前のダミーの空白**: sentencepiece そのもの（`tokenizer.model`）は最初の文が空白で始まっていても付け、tokenizer.json の Metaspace（`prepend_scheme` が always か first）は付けない。後のほうは options の `spaced`（T400 (3)。一覧に当たる項目は無く、`?hf=` の Metaspace の unigram だけ。**変換器が読むのは unigram の道だけで、Metaspace を前分割に持つ BPE の tokenizer.json は `spaced` を言わない**）。**「▁」をどこにも足さない tokenizer.json（Metaspace の never・空白を「▁」に替えるだけの normalizer）は、変換器が `prefixed: "never"` を言い、エンジンは最初の文にも付けない**（T635: unigram の道で、`prefixed_texts()` も `metaspaced()` も言わないとき。本物と ID 列で同じ: `tests/test_prefixed.py`）。**書式から何かを外す・足す変更は、sentencepiece 系と byte-level の両方の項目で送る ID を比べる。**
- **変換の transform** は `None` か `TRANSFORMS`（`convert/plan.py`）の名前で始まる段（`permute` / `transpose` / `heads` / `part` / `row` / `rows` / `scale` / `one` / `plus` / `decay` / `taps`）か段の並びで、知らない名前はどの読み手も拒否する。
- **実物のモデルの固定値（T86）。** 合成モデルでは「動くが文章が壊れる」を捕まえられないので、実物の greedy の 16 トークンを固定した（float32）。**取り込み元を替えたら、前の道を通る固定値が残っているかを見る**。`--write` は `--only` と一緒には使えない（1 つだけなら JSON を手で直して `--only` で確かめる）。
- **yarn の RoPE**: 元の文脈の中で 32 回以上回る対はそのまま、1 回以下は factor 倍遅く、間は等間隔に移り、**cos と sin に 0.1 ln(factor) + 1 を掛ける**（`rope_magnitude()`。落としてもエラーにならない）。ほかの設定も transformers 5.16.1 のとおり（`beta_fast`・`beta_slow`・`truncate`・`attention_factor`・`mscale`）、読む鍵は `convert/config.py` の `YARN_KEYS`。**factor と元の文脈も transformers 5.16.1 のとおり**（T541、`yarn_contexts()`: 元の文脈が無ければモデルの `max_position_embeddings`、factor が null なら「モデルの文脈 ÷ 元の文脈」。書いてある factor はその比と違っても使う（transformers も警告して使う）、factor の鍵が無いか元の文脈が null なら断る。config の上の階の `original_max_position_embeddings` は読まない: transformers が上に置くのは自分の欄に持つ Phi-3 の config だけで、`LlamaConfig` は standardize の後に付ける。PLaMo 3 のように家族が `after()` で作る yarn には当てない）。ほかの鍵（**`attn_factor` は transformers が捨て、vLLM と llama.cpp が掛ける**）は断る。transformers とは CI の `tests/reference_yarn.py`。**ページの文脈（4096）では yarn のほうが素の RoPE より perplexity が高い**ので、一覧の Ternary Bonsai 3 つは項目の options に `rope_scaling: {}`（`formats.js` の `PLAIN_ROPE`。`{}` は「縮めなし・倍率 1」、`null` は使わない: `jsnull`）。**float32 のチェックポイントは表をファイルに持ちエンジンは options を見ない**（`tests/fixed_outputs.py` の `with_the_entrys_rope()`）。覆す条件: Prism ML が推論に yarn を指定していると分かる、ページの文脈の切りを元の文脈より上に上げる。
