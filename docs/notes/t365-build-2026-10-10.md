# T365: ビルドに載せる形と TypeScript の決まり（設計、2026-10-10）

設計だけで、製品のコードには触っていない。数字はこの開発機（a1-free、Node 24.20.0、Astro 7.3.3、Vite 8.3.0、rolldown 1.2.9）で、`.tmp/t365/` の捨ての写しに本当に入れて取った。速さは 1 つも決めていない（開発機の数字で決めない決まり）。CI は回していない（記録と設計だけ）。

## 0. 結論

- **載せる。** `public/` の JavaScript（`coi.js` と `coi-test/` を除く 63 ファイル）を `src/runtime/` に移し、隣を読む形をふつうの静的な import にして、Vite に worker の入口ごとに束ねさせる。Python は zip 2 つ、カーネルの wasm と一緒にビルドの産物として `src/runtime/built/` に置き、どれもハッシュ付きの名前で `_astro/` に出る。`coi.js` は `public/` のまま、**1 字も変えない**。
- **持ち主の 3 つの物差し（単独で試験できる・機能を足しやすい・モデルを足しやすい）だけなら、得は小さい。** 部品を単独で試験できるかは変わらず、モデルを足すときに触る場所も変わらない。減るのは「部品を 1 つ足すときの決まり」だけ（窓口の一覧・`?v=` の行・`python.js` の一覧）。載せる訳は別の 3 つ:
  1. **型はいまの形では部品をまたげない**（測った: §4.1）。`await import(new URL(…?v=…))` で取った名前は tsc には `any` で、綴りの誤りも見ない。静的な import にすれば見えるが、束ねずに静的な import にすると `?v=` が落ちる（10 分のキャッシュで 2 つのデプロイが混ざる）。T368 をやるなら T367 が要る。
  2. **最初の訪問の要求が 51 → 18**（Chrome で測った。GPU のある端末はさらに 23 → 3）。
  3. **デプロイの境目で、古いページが新しいファイルを黙って動かすことが無くなる**（§2.3。いまは後から取るファイルで起きうる）。
- **危なさは 3 つで、どれも検査を置ける**: (a) 束ねた worker のファイル名が `coi.js` の写しの決まりと合わないと、古い写しが消えないか、同じ名前の 2 つが互いを消す（測った。設定と、ビルドの後の検査 1 つで防ぐ）。(b) 束ね手は minify しなくても定数の式を書き換える（測った）ので、「同じ文」は証明にならず、束ねた物そのものを試験と CI の速さの比べに通す。(c) 試験の道具 8 つが今の import の書き方を文として読んでいる（先に直す: T367.1）。
- 「載せずに、いまの場所で型を付ける」は、部品をまたぐ型が付かないので勧めない（付くのは 1 つで立つファイルの中だけ）。

### 2.1 いまの決まり（`public/coi.js`）

### 2.2 測って分かった穴 2 つ

- **Vite の worker の既定の名前は `名前-ハッシュ.js`**（ハイフン）。`family()` の式に当たらず、27 ファイルが「家族なし」になった（デプロイのたびに古い写しが残り続ける）。`vite.worker.rolldownOptions.output` の `entryFileNames`・`chunkFileNames`・`assetFileNames` を `_astro/[name].[hash]…` にすると当たる（測った）。
- **別のグラフの同じ名前の塊は、互いの写しを消す。** 最初の版では `gpu`（モデルと `/benchmark/` の 2 つの入口がどちらも `gpu.js`）・`kept`（ページと worker）・`shaders`（鍵だけと全部）が 2 つずつ出て、`family()` では同じ家族だった。片方を取るともう片方の写しが消え、オフラインで開けなくなる（落ちるのでなく、GPU が黙って CPU になる、など）。直した形（測った: 31 ファイルが全部別の家族）: `/benchmark/` の入口に `benchmark-` を付ける（`entryFileNames` の関数）、ページは `kept.js` を静的に読む、worker は鍵を `shaders/key.js` から読む（塊の名前が `key` になる）。
- **見張り**: ビルドの後に `tests/dist-check.mjs`（新しい。デプロイにも入れる）: `_astro/` の全部の名前に `coi.js` の `family()` そのものを当て、家族が重なるものと家族の無いものがあれば落とす。`dist/` の根に `coi.js`・`coi-test/`・`models/`・ページのほかが無いことも。

### 2.3 デプロイの境目

GitHub Pages はデプロイで全部を入れ替え（古いハッシュの名前は 404 になる）、どのファイルも 10 分キャッシュさせる。

| 場合 | いま（`?v=`） | ハッシュ付きの名前 |
|---|---|---|
| 新しい HTML | 全部を新しい `?v=` で取り直す | 中身の変わったファイルだけ取る |
| 古い HTML（10 分のキャッシュか、開いたままのタブ）が、前に取ったファイルを頼む | HTTP のキャッシュか写しから（古いもの） | 同じ |
| 古いページが、**まだ取っていないファイル**を頼む（変換器・保存の台帳・GPU の Worker・`/benchmark/` の節の Worker） | **サーバは `?v=` を見ないので新しいファイルを返す。古い worker が新しい部品を動かす**（黙って混ざる。その応答は古い `?v=` の鍵で写しにも残る） | **404**（混ざらない） |
| オフライン | 写しの HTML と、その版の写し | 同じ。新しい版を一部だけ取った後は、取っていない物が無い |

- 混ざる場合がはっきりした失敗に替わる。訪問者に見える新しいことは、この 404 のときの文 1 つ（**文面は持ち主**。案:「The site was updated while this page was open. Reload the page to go on.」）。いまある失敗の道（「Could not fetch …」、節の「the worker failed」）に出るので、文を足さなくても壊れはしない。
- 既にページのスクリプト（`_astro/index.….js`）は同じ境目を持っている（T355 から束ねている）。広がるのは worker の後から取る分。

### 2.4 持ち主の端末が先に要るものと、要らないもの

- **要らない（CI の 3 つのエンジンとオフラインで出す）**: T367 の全部。`coi.js` は変えない。変わるのは「このサイトのどの URL が写しに入るか」だけで、それも今ある `/_astro/` の決まりに乗る。
- **要らないが `coi.js` に触る（別の歩: T367.6）**: T367 の前の版が残した `?v=` の写し（worker・forward・shaders・Python などこのサイトのファイル約 70 個）は、もう誰も頼まないので消えない。activate のときに、同じオリジンで `v=` のある写しを捨てる 1 つの輪。このサイトのファイルの写しだけで、ほかのサイトの応答にも隔離のヘッダにも触らない。
- **持ち主の端末が先に要る（どれも予定に無い）**: `isolated()`（COOP・COEP を足す所）、jsDelivr と huggingface.co の応答を通す所と写す所、`KEPT` の名前を上げて Pyodide の写しごと捨てること。T367 の途中でここに触る必要が出たら止める。

## 4. TypeScript の決まり（問い 4）

### 4.1 いまの場所では部品をまたげない（測った）

`public/forward/` を写して `threads.js` の取る名前を 1 つ誤らせ（`BETTER` → `BETTERX`）、`tsc`（7.0.2、`allowJs`・`checkJs`）にかけた: import の行は「TS7036: Dynamic import's specifier must be of type 'string', but here has type 'URL'」で、取った名前は `any`。相手に `BETTERX` が無いことは言わない（後で `BETTER` を使う行が「Cannot find name」と言うだけ）。

### 4.2 `tsconfig`

環境ごとに 3 つ（DOM と WebWorker の型は 1 つのプログラムに入れられない）: `tsconfig.page.json`（`src/page/`・`src/benchmark/`・`src/models/` など、`lib: DOM`）、`tsconfig.worker.json`（`src/runtime/`、`lib: WebWorker`、`types: @webgpu/types`）、`tsconfig.sw.json`（`public/coi.js` だけ、`checkJs`）。共通:

```json
{ "strict": true, "noEmit": true,
  "erasableSyntaxOnly": true, "verbatimModuleSyntax": true, "isolatedModules": true,
  "allowImportingTsExtensions": true, "module": "preserve", "moduleResolution": "bundler",
  "target": "ES2024", "allowJs": true, "checkJs": false, "skipLibCheck": true }
```

- **型を消すだけの構文に限る**（`erasableSyntaxOnly`: `enum`・`namespace`・引数のプロパティ・デコレータを tsc が断る。Node が走らせる構文と同じ線）。**型だけの import は `import type`**（`verbatimModuleSyntax`: 残った import は全部本物で、束ね手と Node が同じものを読む）。
- **import は `.ts` の拡張子で**（`src/page/` はもうそう書いている）。出力は作らない（`noEmit`）: 走らせるのは Vite と Node で、tsc は検査だけ。
- **`noUncheckedIndexedAccess` は入れない**: 型付き配列の `F[i]` が `number | undefined` になり、1 トークンの道の全部に `!` を書くことになる。
- **1 つずつ締める**: `checkJs` は false のまま、`.ts` に替えたファイルから検査に入る。替えたファイルは最初から `strict`。分からない所は `any` と**書く**（`noImplicitAny` を切らない）: 書いた `any` は数えられ、歩ごとに数を報告する。
- 入れる物: `typescript`（いまリポジトリに無い。写しに入れた 7.0.2 は `src/runtime/` の 63 ファイルを 0.9 秒で見た）と `@webgpu/types`。
- 量の見積もり（写しで、全部を `checkJs`・`strict` にかけた数。直す数ではなく、型を書く場所の目安）: いまの `.ts` 22 ファイルは 12 個。`src/runtime/` は 3,068 個（引数の型 1,300、取り出しの型 384、変数 284、「undefined かもしれない」522）。暗黙の `any` を許すと 988 個で、`/benchmark/` の Worker 532・worker 223・forward 123・gpu 87・`kept` 15・shaders 4・`helper` 4。**532 と 223 と 87 の多くは、分け合う入れ物（`shared`・`state`・`common`）のフィールドが「まだ無いかもしれない」こと**（`'shared.device' is possibly 'undefined'` の形が 461）: T378（状態に持ち主を）を先にやる順（T376 の案）は、この数でも支えられる。

### 4.3 1 トークンの道は変わらない、の証明

## 5. 速さ（問い 5）
