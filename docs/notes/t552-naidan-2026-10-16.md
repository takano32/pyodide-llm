## まとめ

- **naidan は「サーバの要らない、ブラウザの中で動く AI のチャットのアプリ」**（Vue 3 と Vite と TypeScript、MIT、作者 Ryo Ota（nwtgck）、0.54.1-dev）。ブラウザの中の推論は **llama.cpp を wasm にした自前のパッケージ**（`llama-cpp-browser-core`、WebGPU か CPU）と transformers.js と Chrome の Prompt API で、ほかに OpenAI の形の API と Ollama にもつなぐ。会話の履歴・分岐・グループ・タブの間の同期・Markdown と数式と図の描き・画像と音声の生成・ブラウザの中のシェルまで持つ大きなアプリ（README は「ほとんどの行は GPT・Gemini・Claude が書き、人の読みはふだんより少ない」と言う）。
- **エンジン・取得・変換・スレッド・メモリで取り込めるものは無い**: エンジンは llama.cpp の wasm（T504 で取らないと決めた形）で、取得は GGUF のファイルを OPFS に丸ごと置く。こちらの Range の部品・届く順の変換・16 GiB・本数の検索のほうが先にいる。
- **取り込む値があるのは画面の小さな工夫 4 つ**: (1) 取得の **残り時間**（T553）、(2) 答えの **描きを束ねる**（1 トークンごとに文を足し直さない: T554）、(3) `/benchmark/` で **同じ測りを頭と終わりに** 置いて発熱のずれを見せる（T555）、(4) 答えを **Markdown で描く**（T556、持ち主に聞く）。ほかに既にあるタスクへの材料が 3 つ（T520・T548・T137）と、調べの途中で気づいた 1 つ（T557: モデルのページの取得中も画面を消さない。naidan の形ではない）。
- いちばんスマホの訪問者に効くのは T553 と T557（初めての訪問の 379 MB の取得が、あとどれだけか分かり、画面が消えて止まらない）。
