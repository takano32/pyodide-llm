### Granite 4.x

- 実物: `ibm-granite/granite-4.2-3b` @`e459acceac81e5fe67c07d9cfc72329a332e7eb1`（2026-08-07、apache-2.0、3.66B、言語に ja）。config: `model_type: granite`、hidden 2560、40 層、heads 40 / kv 8、`attention_multiplier: 0.015625`、**`embedding_multiplier: 1.0`・`logits_scaling: 1.0`・`residual_multiplier: 1.0`**、tie false、silu、rope_theta 1e7。4.2-8b（@`f8de16cd…`、8.79B）も 3 つが 1.0 で `attention_multiplier: 0.0078125`。

### Mistral の新しいトークナイザ（tekken）の前分割

- 型: `[^\r\n\p{L}\p{N}]?[\p{Lu}\p{Lt}\p{Lm}\p{Lo}\p{M}]*[\p{Ll}\p{Lm}\p{Lo}\p{M}]+|[^\r\n\p{L}\p{N}]?[\p{Lu}\p{Lt}\p{Lm}\p{Lo}\p{M}]+[\p{Ll}\p{Lm}\p{Lo}\p{M}]*|\p{N}| ?[^\s\p{L}\p{N}]+[\r\n/]*|\s*[\r\n]+|\s+(?!\S)|\s+`。大文字と小文字の種類（Lu・Lt・Lm・Lo・Ll・M）を分けて見るので、エンジンの文字の種類（`CharClasses`）を細かくする必要がある。
- 同じ型のもの（実物の tokenizer.json で確かめた）: `mistralai/Ministral-8B-Instruct-2410` @`2f494a19…`（8.02B、ライセンス mrl＝研究用、言語に ja）、`nvidia/Mistral-NeMo-Minitron-8B-Instruct`、`cyberagent/Mistral-Nemo-Japanese-Instruct-2408` @`8591f785…`（12.25B、apache-2.0、日本語）、Nemotron の系統、Apertus。
- **Phi-4 mini と kanana-2 は似た別の型**（各語の後ろに `(?i:'s|'t|…)?` が付き、数字が `\p{N}{1,3}`）。文字の種類を細かくすれば、型を 2 つ足すだけで両方開く。
- Ministral 8B は config に `layer_types`（sliding_attention を含む）と `sliding_window: 32768` がある。文脈を窓より短く切れば窓なしと同じ（T125 の考え）で、`check_config()` は今も通している。
- **Mistral Nemo 12B は 16 GiB に入るかが境界**: int8 と relaxed の補正で 12.25B × 1.25 = 15.3 GB（14.3 GiB）、KV を足して約 15.3 GiB（見積もり）。実測が要る。

### tokenizer.json の sentencepiece 流の BPE

- 実物: `cyberagent/CAT-Translate-7b` @`e36edfc6858a9a6ba41f8d9fa34427f3d8461eca`（7.49B、mit、日英翻訳、2026-02）。**`tokenizer.model` が無く**、tokenizer.json は BPE（`byte_fallback: true`・`fuse_unk: true`）で、normalizer が「先頭に ▁ を足す」「空白を ▁ に替える」、pre_tokenizer は null。変換器は「前分割を知らない」と断る（T125 の記録は「`"head_dim": null` を読めるようにした」までで、その先のトークナイザで断られていた）。
- 同じ形: ministral/Ministral-3b-instruct、Mistral 7B の派生の一部、**Gemma 4**（tokenizer.json しか無い）、Phi-3 と Gemma 2 / 3（こちらは `tokenizer.model` もあるので今も読める）、Nanbeige。
- 足すもの: merges の順位を点数にして、今ある llama2.c 形の BPE の語片に直す読み手（byte-level BPE を T63 で入れたのと同じ考え）。normalizer の形（Prepend と Replace）を確かめて、ほかは断る。
- GGUF の重みは `mradermacher/CAT-Translate-7b-GGUF` @`cd7d970b…` に Q8_0（7,955,662,016 バイト）。

### yarn の残りのキー

- 実物: `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B` @`6e8885a6ff5c1dc5201574c8fd700323f23c25fa`（8.19B、mit、72 万ダウンロード）の `rope_scaling` は `{rope_type: yarn, factor: 4.0, original_max_position_embeddings: 32768, attn_factor: 0.8782488562869419}`。T235 の `check_config()` は factor と original 以外のキーを断る。
- **`attn_factor` は transformers が読まない名前**（transformers の名前は `attention_factor`。無ければ既定の 0.1 ln(factor) + 1 = 1.139 を使う: エンジンの `rope_magnitude()` と同じ値）。llama.cpp の側がこの名前を読むかは確かめていない（未確認）。読むなら 2 つの実装で score の鋭さが違うことになるので、**どちらを本物とするかを決めてから入れる**（カードの勧める実行のしかたと、両方の perplexity）。

### Phi-3 と Phi-4 mini

- 実物: `microsoft/Phi-3-mini-4k-instruct` @`f39ac1d28e925b323eae81227eaba4464caced4e`（3.82B、mit）。config: `model_type: phi3`、hidden 3072、32 層、heads 32 / kv 32、tie false、`sliding_window: 2047`、rope_scaling なし。transformers の `Phi3Attention` は q・k・v を 1 つの `qkv_proj` に、`Phi3MLP` は gate と up を 1 つの `gate_up_proj` に持つ（変換で割る。GPT-2 の `c_attn` を割る道がある）。**今の transformers は Phi-3 でも `sliding_window` を掛ける**ので、文脈を 2047 で切る（Mistral v0.1 と同じ扱い）。

- 順: Phi-3 mini 4k（割るだけ）→ tekken の前分割の仕事の後に Phi-4 mini（longrope と回す割合）。

### そのほかの小さな穴

- **BitNet b1.58**（`microsoft/bitnet-b1.58-2B-4T-bf16` @`27668139…`、2.41B、mit、英語）: Llama に、`hidden_act: relu2`（2 乗の ReLU）、o の前と down の前の RMSNorm（`attn_sub_norm`・`ffn_sub_norm`）、重みを実行時に 3 値に丸める（`quantization_mode: online`）を足したもの。変換のときに 3 値にすれば T230・T231 の 3 値の道に乗る。活性値も 8 ビットに丸めるモデルで、うちの 7 ビット / 8 ビットの活性値との差は測ることになる。トークナイザは llama3 の型で通る。GGUF は名前の検索では見つからなかった。

### LFM2 / LFM2.5（勧める）

- 実物: `LiquidAI/LFM2.5-350M` @`9e6c6ccf…`（0.35B、言語に ja）、`LFM2.5-230M` @`40cb2ad3b3044d5a41eee083a6103c8b523afa45`（0.23B、言語に ja、2026-06）、`LFM2.5-1.2B-JP-202606` @`52b8b4475311a63bf839c6494f78f8ad59d13515`（1.17B、「最新の汎用日本語チャットモデル」とカードが書く、2026-05）、`LFM2.5-1.2B-Instruct`（11 万ダウンロード）、`LFM2.5-2.6B`。ライセンスは `lfm1.0`（other。条文は読んでいない: 未確認）。
- config（1.2B-JP-202606）: `model_type: lfm2`、hidden 2048、16 層、`layer_types` は conv・conv・full_attention・… の並び、heads 32 / kv 8、`conv_L_cache: 3`・`conv_bias: false`、rope_theta 1e6、語彙 65,536、埋め込みと分類器は同じ表。230M は hidden 1024・14 層・heads 16 / kv 8 で、`block_ff_dim` の決め方が違う（`block_auto_adjust_ff_dim: false`）。
- 層（transformers の `modeling_lfm2.py`）: `x += 演算(norm(x))`、`x += FFN(norm(x))`。演算は層の種類で 2 つ。
  - attention の層: q と k に head ごとの RMSNorm（Qwen3 と同じ形）、GQA、RoPE。
  - **畳み込みの層**（`Lfm2ShortConv`）: `in_proj`（dim → 3 × dim）の出力を B・C・x に割り、`B × x` に幅 3 のチャンネルごとの畳み込み（`groups = dim`）を掛け、`C` を掛けて `out_proj`。生成のときに持つ状態は、層ごとに直前の 2 位置ぶんのベクトルだけ（KV は要らない）。
  - FFN は SwiGLU（w1・w3・w2）。
- 足すもの: 層の種類の並び（Qwen3.5 の `linear` の options と同じ考え）、畳み込みの層の forward（行列積は今のカーネル、掛け算と幅 3 の畳み込みは小さなカーネル 1 つ）、その層の状態、GGUF の `lfm2` の名前。GPU は畳み込みのシェーダが 1 つ要る（無い間は CPU）。
- トークナイザは llama3 の型で読める。書式は 1.2B-JP-202606 が読め（ChatML）、350M は読めない。作り手の Q8_0 の GGUF がある（`LiquidAI/LFM2.5-350M-GGUF` @`657e078c…` 379,217,632 バイト、`LFM2.5-1.2B-JP-202606-GGUF` @`448ba3f7…` 1,246,253,344 バイト）。
- int8 の見積もり: 230M 約 0.26 GB、350M 約 0.40 GB、1.2B 約 1.3 GB。**日本語の使える軽いモデルが 2 つ増える**（既定は変えない: 方針 4）。

### Gemma 3（text）

- 原本（google/gemma-3-270m-it・1b-it）はゲート付き（manual）。ゲートなしの写しが unsloth にある（Llama 3.2 と同じ扱いになる: 方針 8）。ライセンスは gemma。
- 実物: `unsloth/gemma-3-270m-it` @`23cf460f6bb16954176b3ddcc8d4f250501458a9`（0.27B）と `unsloth/gemma-3-1b-it` @`5b11413a…`（1.00B、原本は 319 万ダウンロード）。config（270m）: `model_type: gemma3_text`、hidden 640、18 層、heads 4 / kv 1、**head_dim 256**、`hidden_activation: gelu_pytorch_tanh`、`sliding_window: 512`（6 層のうち 5 層が sliding_attention）、`rope_theta: 1e6` と `rope_local_base_freq: 1e4`、`query_pre_attn_scalar: 256`、softcap は 2 つとも null、語彙 262,144。
- 層（`modeling_gemma3.py`）: norm が 4 つ（attention の前と後、FFN の前と後）。norm は `x × (1 + w)`。q と k に head ごとの norm。FFN は GELU のゲート（GeGLU）。埋め込みに √hidden を掛ける。窓の層は直前の 512 位置だけを見て、theta 1e4 の RoPE を使う。
- 足すもの: 後ろの norm 2 つ（EXAONE 4.0・OLMo 2 の「後ろに置く並び」と同じ部品）、(1 + w) は変換で畳む、√hidden は埋め込みと分類器が同じ表なのでエンジンに倍率が要る（Granite 4.1 と同じ部品）、GeGLU（今の gelu カーネルと掛け算）、**窓つきの attention**（CPU は見始める位置をずらすだけ。GPU の flash attention に下限を渡す）、RoPE の表を層の種類で 2 つ。
- トークナイザ: `tokenizer.model`（sentencepiece の BPE、262,144 語片）は読み手を通る。tokenizer.json は `KeyError: 'Regex'` で落ちる（下の 7 節の 2。worker は `tokenizer.model` に移るので害は無い）。書式は読めない（手で書く: `<start_of_turn>user\n{prompt}<end_of_turn>\n<start_of_turn>model\n`。本物と ID を突き合わせること）。
- GGUF: `unsloth/gemma-3-270m-it-GGUF` @`c90975db…` の Q8_0 は 291,546,144 バイト、`ggml-org/gemma-3-1b-it-GGUF` @`f9c28bcd…`。
- 270M は埋め込みが 262,144 × 640 = 1.68 億で、全体の 6 割。int8 で約 0.3 GB。

### Gemma 4

- 実物: `google/gemma-4-E2B-it` @`3e22461f65e89153144f8adb70e3b8c2cc9845a7`（apache-2.0、ゲートなし、303 万ダウンロード、全体 5.12B）、`gemma-4-E4B-it`（8.00B）、`gemma-4-12B-it`（11.96B、`gemma4_unified`）。絵と音も受けるモデルで、ページは `text_config` の言語モデルだけを読むことになる。
- E2B の text_config: hidden 1536、35 層、head_dim 256 と `global_head_dim: 512`、**`hidden_size_per_layer_input: 256`**（層ごとの埋め込みの表 262,144 × 256 × 35 = 23.5 億。全体の半分近く）、**`num_kv_shared_layers: 20`**（後ろの 20 層は前の層の K と V を使い回す）、`use_double_wide_mlp`、窓 512、RoPE は窓の層が theta 1e4・全体の層が `proportional`（回す割合 0.25、theta 1e6）、`final_logit_softcapping: 30`。transformers（`modeling_gemma4.py`）にはほかに v の norm、層ごとの倍率（`layer_scalar`）がある。
- 12B は別のクラス（`Gemma4Unified`）で `attention_k_eq_v: true` など。int8 と補正で 11.96B × 1.25 = 15.0 GB で、**16 GiB に入るかは境界**（絵と音の塔を読まなければ少し減る: 未計測）。
- トークナイザは tokenizer.json だけ（sentencepiece 流の BPE。上の B の読み手が前提）。
- **Gemma 3 を先に入れ、その部品（窓・norm 4 つ・GeGLU・倍率）の上に足す**。

### 今は勧めないもの

## 5. D: 入らない・合わない

- **量子化済みの再配布**（278 件）: bnb・AWQ・GPTQ・FP8・MLX。どれも原本が別にある。

## 7. 途中で見つけたこと

1. **API の `language=ja` は効かない**（0 節）。日本語のタグで絞るのは `filter=ja`。T81 の「日本語の一覧 1000 件」は実際には普通のダウンロード順だった見込み（T81 の結論は組織ごとの一覧から出ていて、変わらない）。
2. **前分割の Split の型が `String` の tokenizer.json で、変換器が `KeyError: 'Regex'` で落ちる**（`pretokenizer_name()` の `step["pattern"]["Regex"]`）。Gemma 2 / 3 / 4（`{"String": " "}` の Split）と PleIAs の 5 つ、polyglot-ko で起きる。ほかの断りは `ValueError` で言葉になっている。worker.js はどの例外でも次のトークナイザ（`tokenizer.model`）に移るので、開くものは今も開く。困るのは全部断られたときで、訪問者に出る最初の断りが言葉でなくなる。直しは 1 行（`Regex` が無ければ「知らない前分割」と断る）。
3. **CAT-Translate-7b は T125 の後も開いていない**（トークナイザで断る。3 節）。
4. **Qwen3 と Qwen2.5 の派生には BOS を言わないものがある**（2 節の shisa の 2 つと CAT の 2 つ）。本家の config.json には `bos_token_id: 151643` があるが、派生の config.json からは消えていて、tokenizer_config.json にも BOS が無い。変換器は 1 を既定にするので、`?hf=` で開くと文が `"` のトークンから始まる。**BOS が無く、語彙に `<|endoftext|>` があるときはそれを BOS にする**、という読みを変換器に足せば `?hf=` でも直る（`CONVERTER` を上げることになるので、次に上げる回に）。一覧に入れるぶんは項目の options で直せる。
5. **日本語のタグの付いた小さいモデルの種類**（`filter=ja` の 1,500 件のうち safetensors のある 9.5B 以下 429 件）: lfm2 89・llama 81・granite 60・rwkv7 19・qwen3 13・qwen3_5 22・lfm2_moe 13・qwen2 11・gpt2 11・cohere2 11・phi3 7・mistral 7。多言語のモデルが日本語を挙げるようになり、日本の組織の外のモデルが多い。
6. **Granite は 4.1 と 4.2 でトークナイザの前分割も書式も違う**（4.1 は llama3 の型で書式が読め、4.2 は ByteLevel で書式が読めない）。同じ名前の系統でも、版ごとに実物を読む。
7. 一覧に JiRackUltra_1b（253 万ダウンロード）がまだ上位にある。T81 の見立て（出どころが確かめられない）は変えていない。
