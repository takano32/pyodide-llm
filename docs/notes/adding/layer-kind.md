# 層の種類（状態を持つ層）を足す

AGENTS.md の「物を足す手順」節から移した（T658、2026-11-12）。要点は AGENTS.md に。

どの手順も「触る所」と「忘れると誰が教えるか」まで書く。**教えないと書いてある所は、黙って別の動きになる**。試験の側の 2 つ目の写し（`FACTS`・`ORDER`・`KINDS` など）はわざと 2 回書いてあるもので、足したら一緒に直す。

### 層の種類（状態を持つ層）を足す

**Python**: (a) `layout.py` に `Stateful(名前, parse, layers)` と行の関数、`FORM` に種類の名前の鍵。(b) `engine/model.py` に 1 トークン（`Llama` のメソッド）と状態を作る関数を書いて `STATEFUL_LAYERS` に 1 項（名前で持つ: メソッドを属性に置くと循環参照）。(c) 層の番号のほかに要る計画の鍵（`Llama` は FORM の鍵を `form_of()` で読む: T639.1）。付いてくるもの: 形の突き合わせ（`stateful_form()`）、置き場、`layers[l].kind`、計画の種類の名前の鍵（層の番号、無い種類は None: `forward_plan()` が `stateful_kinds()` から、T639.6。ページが読む鍵は `Plan` に足す: `plan-keys-check` が教える）、位置 0 で状態を消すことと順でない位置の断り（`follow()`）。1 つの種類の層が 1 層だけのモデルは変換器が断る。

**JavaScript**（`createForward()` と `footprint()` には触らない）:
1. `src/runtime/forward/<種類>.ts` に `export const <種類>: Kind`（手本は `convolution.ts`）: `frame(sizes)`、`make(core, count)`（`matrix("名前")`・`floats("名前")`、状態は `state()` の並びどおりに `room.alloc()`。`{ layer: (place) => (count, pos0) => { … }, clear() }` を返す）、`state(sizes, count)`、`layers(form, count)`、鍵と値をキャッシュに持つなら `cached(sizes, form, layers)`、要れば `widths(form)`。
2. **状態を読んで書く段をスレッドに出すなら、読む所と書く所を分ける**（2 枚持つ: 止まったスレッドの段をやり直しても同じ数になる。`linear.ts`）。取りまとめ役だけが段の外で触るなら 1 枚でよい。
3. `forward/kinds.ts` の表の**最後**に 1 行。型: `contracts/plan.ts` の `LayerKind` と `TensorName`、`contracts/form.ts` の `Stateful`。
4. 試験: `tests/layer-parts-check.ts` に種類の節と表の順、`tests/plan_facts.py` の `cases()`、`tests/engine_plans.py` に家族。
5. 状態を持つ層のあるモデルは何も書かなければ GPU に置かれない。**GPU にも置くなら**: `make()` の返す物に `staging: { bytes, put(to), take(from) }`（GPU が持つ形の状態のバイト数と、staging に書く・戻す関数）、種類に `staged(sizes, count)`（`footprint()` が数える）、GPU の
