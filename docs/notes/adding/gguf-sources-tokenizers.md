# GGUF の型・取り込み元の種類・トークナイザの候補を足す

AGENTS.md の「物を足す手順」節から移した（T658、2026-11-12）。要点は AGENTS.md に。

どの手順も「触る所」と「忘れると誰が教えるか」まで書く。**教えないと書いてある所は、黙って別の動きになる**。試験の側の 2 つ目の写し（`FACTS`・`ORDER`・`KINDS` など）はわざと 2 回書いてあるもので、足したら一緒に直す。

### GGUF の型・取り込み元の種類・トークナイザの候補を足す

- **GGUF の型**: `convert/readers.py` に NumPy の読み手と `SOURCES` に 1 行。**llama.cpp の 256 個の塊の型は `convert/superblocks.py` に**（llama.cpp と同じ結び方で: 0 の符号まで同じに）読み手と `SUPERBLOCKS` の 1 行、**塊のバイト数は `engine/dtypes.py` の `BLOCKS`**（2 つ目の写しは `tests/test_blocks.py` の `SIZES`）。**読むだけで塊のまま持たない型は `WIDENED` の 1 行で `BLOCKS` には足さない**（その型の層が 1 つでもある束は丸ごと広げる。`tests/test_widened.py`）。32 個の塊の型は `readers.py`。**同じ番号で塊の大きさが 2 通りある型は読まない**（ggml の 42 = Q2_0）。**エンジンは塊の行を NumPy で読むときにだけ `convert.superblocks` を import する**（読み手と符号表を `engine.zip` に入れないため）。試験は `tests/test_superblocks.py`、`tests/test_dtypes.py`、`tests/fork_readers.py` の表、`python tests/test_superblocks.py` で fixture。**断りの文は読める型の一覧を言わない**（「… is stored as I64, which is not read.」: 持ち主の決め、T501。型を足しても文は変わらない）。元の実装から表や行を写したら著作権と許諾文の全文（方針 10）。**読み手は変換器の側に置く**（`converter.zip` は変換のときだけ）。カーネルの読み手を足すならファイルに出ないバイト値も NumPy と同じに（smoke が全バイト値で比べる）。**「知らないテンソルは読み飛ばす」を使うときは、意味が変わらないかを確かめる**。llama.cpp が値や並びを変えて書くテンソルは家族の `gguf_marks` の印（見出しの `done`・`tiled`・`transposed`・`split`・形の `axis`）で戻す（「家族を足す」の 3）。
- **取り込み元の種類**: `convert/conduct.py` に `opened(hf, config, make)` の形のジェネレータ（頼みを yield し、`Weights(…)` か `Another(訳)`）と `SOURCES` に 1 行（試す順）。頼みは今ある 5 種類で書く（足りないときは先に持ち主に言う）。試験: `tests/worker-fetches-check.ts` の `CASES` と `--write`（差分を読む）、`tests/test_conduct.py`（GGUF の頭は `tests/test_conduct_gguf.py`）。
- **llama2.c のチェックポイントの取り込み元の種類**（変換しないもの: サイトのモデル・ディスクの 2 つのファイル・2 つの URL。T641.4）: `worker/sources.ts` の表 `SOURCES` に、モデルから `SourceKind` を作る 1 行（ステータス行の語 `verb`、チェックポイントの source とトークナイザのバイトと見出しを開く `opened()`、一覧の `options`（無ければファイルから: `load.ts` の `localOptions()`）、エンジンが 2 つを 1 つのモデルと読めないときの文 `misread()`、準備完了の後の `ready()`）と、種類を選ぶ `sourceOf()` に 1 つの枝、`contracts/messages.ts` の `Listed` に型。`load.ts` は触らない。試験は `tests/worker-parts-check.ts` の load.js の節（種類ごとに準備完了まで・見出し・ステータス行）。**一覧の項目も「2 つの URL」の種類で開ける**（T653: 項目の型 `Linked` の `url: { checkpoint, tokenizer }`。チェックポイントは HF の 40 桁のリビジョンの番地（`models-check`）、`tokenizer` は名前だけでサイトの `models/` の下から: worker が `new URL(名前, root の models/)` で引く。options は一覧のものとファイルの dtype。保存はしない: 2 回目もネットから。例は `stories42M-f32`）。
- **置き場（答え手）**: `worker/conduct.ts` に `{ answers, missing }` を返す関数と、`worker/convert.ts` の選ぶ 1 行。`tests/worker-conduct-check.ts`。
- **トークナイザの候補**: `conduct.py` の `TOKENIZERS` に名前（`.json` で終われば tokenizer.json）、ページの `src/page/folder.ts` の `TOKENIZERS` は `python_facts.py` が書き出す（T628.2: 手で書かない。**門の文が名前から組まれて変わる**ので持ち主に見せてから。`index.astro` のボタンの `title` も手で）、`tests/conduct_hub.py` の `THREE` と fixture。
- **語彙の読み手（トークナイザのファイルの種類）**: `convert/vocabulary.py` に読み手（ファイルのバイトから `Vocabulary` を返す）と `VOCABULARIES` に 1 行、名前から種類を選ぶのは `vocabulary_kind()`。サイトのモデルのビルド（`convert_hf.py` の `convert_tokenizer()`）も同じ `vocabulary_of()` を段取りと同じ順で呼ぶので触らない（T640.7。`tests/test_convert_hf.py` が tokenizer.bin をページの `Conversion` と比べる）。GGUF の語彙の種類は `convert/gguf.py` の `GGUF_VOCABULARIES`。**頭・止まり・書式の規則を足すなら `convert/beginning.py` の `beginning_and_stops()`**（`Conversion` は触らない）: 試験は `tests/test_beginning_rules.py` の形で値から（重みも見出しも要らない）、変換の全部を通す試験は `test_beginning.py` の形、options の全部は `tests/test_conversion_values.py` が持つ（options を変えるなら `CONVERTER` の回に一緒に直す）。
- **量子化の札**: `src/page/repository.ts` の `QUANTIZATIONS` の質の順の位置に 1 行と `tests/repository-check.ts` の `ORDER`。読み手の無い札は足さない。**頭の 4 つの順は持ち主のもの**。
- **道具が変換するとき**は段取りを回す（`tests/conducting.py` の `converted(答え手, hf, dtype=…, sink=Mapped(出力))`。重みを読まないなら `weights=False, sink=Nothing()`）。大きさだけ知りたいときも何もしない sink を渡す。**`listed(path)` は名前が `.gguf` で終わる道をファイルと読む**: フォルダの名前に `.gguf` を残さない。
