## 形

| | 1.7B | 4B |
|---|---|---|
| dim・FFN の内側・層 | 2048・6656・28 | 2560・10240・36 |
| head | 256 が 8 つ、鍵と値の head は 2 つ（q は 2048 幅 = dim） | 256 が 16、鍵と値は 4（q は 4096 幅: dim と違う） |
| 窓の層（`sliding_attention`） | 28 層のうち 21（4 層ごとの 4 つ目が全位置） | 36 層のうち 27 |
| 窓・RoPE | 512。窓の層は head 全部（256）を base 1e4、全位置の層は head の先頭 64（`partial_rotary_factor` 0.25）を base 5e6 | 同じ |
| 語彙・文脈 | 131,072・1,048,576（ページは 4096 に切る） | 同じ |
| eps・分類器 | RMSNorm 1e-6（重みそのもの: 1 を足さない）・埋め込みと同じ表 | 同じ |

1 トークン（config.json と `modeling_spark.py` から）:

```
x = 埋め込みの行（倍率なし。流れは float32）
層ごとに:
  xb = norm(x)
  q, k, v = q_k_v_proj xb を切る（q: heads × 256、k と v: kv heads × 256）。bias なし、head の norm なし
  g = g_proj xb（heads 個: head に 1 つ）
  RoPE: 窓の層は head 全部を base 1e4 で、全位置の層は head の先頭 64 を base 5e6 で。どちらも rotate_half の形
        （回す幅の半分ずつを組にする）で、角は回す幅で決まる（θ_i = base^(−2i/回す幅)）
  score = q·k / √256。窓の層は自分を入れて直近 512 位置（transformers の sliding_window の読み）
  o = attention の出力の head h に sigmoid(g[h]) を掛ける（gate_attn_act_mode: sigmoid）
  x += out_proj o
  x += down(gelu(gate xn) × up xn)、xn = norm(x)       gelu は transformers の "gelu": erf の正確な形
logits = 埋め込みの表 · norm(x)
```

## GGUF の見出し（1.7B、Q8_0）

- `general.architecture` は `spark2_5`。鍵: `block_count` 28、`embedding_length` 2048、`feed_forward_length` 6656、`attention.head_count` 8、`head_count_kv` 2、`attention.key_length`・`value_length` 256、`rope.freq_base` 5e6、`rope.freq_base_swa` 1e4、`rope.dimension_count` 64、`rope.dimension_count_swa` 256、`attention.sliding_window` 512、`attention.sliding_window_pattern`（28 個の真偽: 真が窓の層）、`attention.layer_norm_rms_epsilon` 1e-6、`context_length` 1,048,576、`general.sampling.temp` 1.0・`top_p` 0.95・`top_k` 0。
- テンソル（層ごと）: `attn_norm`・`attn_qkv`（3072 × 2048、Q8_0）・`attn_gate`（8 × 2048、**Q8_0**）・`attn_output`・`ffn_norm`・`ffn_gate`・`ffn_up`・`ffn_down`。外: `token_embd`（Q8_0）・`output_norm`。分類器は無い（同じ表）。
- **q と k は Hugging Face の並び**（llama.cpp の NEOX の回し方）: 層 0（窓）と層 3（全位置）の `attn_qkv` を原本の bf16 と比べて、そのままなら最大の差が最大の値の 0.0039（Q8_0 の丸め）、Llama の並べ替え（64 か 256 の幅）を当てると 1.2〜1.6。v も同じ。
- 語彙: `tokenizer.ggml.model` は `gpt2`、`pre` は `spark2_5`。131,072 のトークンと 130,716 の merges が原本の tokenizer.json とどれも同じ（同じ順）。BOS 0・EOS 1・pad 2・unk 5、`add_bos_token` は偽。書式（`tokenizer.chat_template`）がある。

## 語彙と書式（T.343 のための記録）

- byte-level BPE、語彙 131,072、`added_tokens` 113（`<｜start▁of▁sentence｜>` 0・`<｜end▁of▁sentence｜>` 1・`<｜▁pad▁｜>` 2・`<think>` 3・`</think>` 4・`<unk>` 5・`<|System|>`・`<|User|>`・`<|Bot|>`・`<tool_call>` など。special でないものも 13）。normalizer は空。
- 前分割（T.340）: Split `\p{N}{1,3}`（Isolated）→ Split `[一-龥぀-ゟ゠-ヿ]+` → Split の 3 つ目 → `Digits(individual_digits)` → `ByteLevel(use_regex: false)`。DeepSeek V3 の形に近いが 3 つ目の型（` ?[\p{P}\p{S}]+|[\r\n]|…`）と後ろの Digits が違う: 別の名前 `spark2_5`。
- 書式（`chat_template.jinja` 4,648 バイト、tokenizer_config.json の中のものと同じ中身）: 頭に `<｜start▁of▁sentence｜><|System|>\nyou are a helpful assistant.`（system のターンがあればその後ろに 2 つの改行と本文）と `<｜end▁of▁sentence｜>`、ターンは `<｜start▁of▁sentence｜><|User|>…<｜end▁of▁sentence｜>`、答えの頭は `<｜start▁of▁sentence｜><|Bot|>` で、`enable_thinking` が既定で真なら `<think>`、偽なら `</think>`。マクロ `render_content` を呼ぶ（自前の読み手は読めない: jinja2 の道）。
- generation_config.json: 温度 1.0・top-p 0.95・top-k −1（なし）・罰なし。BOS 0・EOS 1。

## T.340 の結果（前分割）

- エンジン: 字の種類の表 `SparkClasses`（`engine/tokenizer.py`）と段の並び `STAGES["spark2_5"]`（数の 1 字ずつ、漢字とかなの塊、3 つ目の型。どの段も前の段の切れ端ごとに Isolated で切り、当たらない所も切れ端）。Digits は数を 1 字ずつに切るので、`\p{N}{1,3}` と Digits を合わせて「数は 1 字ずつ」の 1 段にした（`\p{N}{1,3}` が先に数を切り出すので、ほかの切れ端に数は残らない）。
- 塊の 21,094 字のうち字でないもの: ゠（Pd）・・（Po）・゛゜（Sk）・゙゚（Mn、結合の濁点）・割り当てのない 3 字。どれも塊の印つきでそれぞれの種類（句読点と記号・印・そのほか）に分けた。
- 本物の `tokenizers` 0.23.1 と: pytest（作り物の語彙）、全符号位置（違うのは Python の Unicode 16.0 が割り当てていない U+11DE0〜U+11DE9・U+16FF4〜U+16FF6 の 13 字だけ: ほかの前分割と同じ）、実物の tokenizer.json（240,783 文、`--planes 17` で 2,339,983 文、どれも 0 違い）。
- GGUF: トークン 131,072 と merges 130,716 が同じ（同じ順）。型の数は 1（ふつう）130,959・3（制御）100・4（利用者の定義）13。tokenizer.json で special でない 22 の追加のトークンのうち 9 つを GGUF は 3 と言う（エンジンはどちらも specials に入れるので同じ）。
- deepseek-coder 1.3B（`deepseek-ai/deepseek-coder-1.3b-instruct` @`e063262d`）の前分割は `[\r\n]`・`\s?\p{L}+`・`\s?\p{P}+`・`[一-龥ࠀ-一가-퟿]+`・Digits の 5 段で、別の形（これでは開かない）。

## T.341 の結果（窓と層ごとの RoPE）

- エンジンは今の部品のまま: 局所の層は head 全部を局所の表で（`layer_facts()` の `rotary` は局所の層で head、ほかで options の `rotary`）、ほかは `PARTLY` の表（回す幅の角、`partial_tables()`）。`plan-facts-check` の作り物「局所の層と一部を回す層」（Llama の記録に `local=True, rope=PARTLY`、head 32 のうち 8）でページの forward が NumPy の 1.49e-7 以内。
- 変換器: 窓の層は head 全部（256 の半分ずつを組に）、ほかは先頭 64（32 ずつを組に）と、並べ替えの幅が層で違う。取り込み元の変換を層の番号の関数にできるようにし（`conversion_plan()`）、幅は家族の `turns(config)` が言う。

## T.342 の結果（gate・erf の GELU・名前）

- 行 `head_gate`（wo の後ろ）、活性化 `gelu_erf`、カーネル `geglu_erf`、家族 `spark2_5`、変換 `("rows", 始め, 終わり, 全部)`。
- erf の形: Abramowitz と Stegun の 7.1.26（erf(z) ≈ 1 − (a1 t + … + a5 t⁵) e^(−z²)、t = 1 / (1 + p z)）。GELU は x ≥ 0 で x (1 − h)、それより下で x h（h = poly · e^(−z²) / 2: 負の側で 1 を引かない）。z を 9 で止める（|x| が 12.7 を越えると h は 1e-36 より小さい）。erf そのものからの誤差 4.2e-7（|x| が 3.1 のあたり）、tanh の形は 4.7e-4。
